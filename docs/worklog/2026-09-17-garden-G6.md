# 遊び心地 — 夜が見えない、ホイールが 2 段階、説明が無い（G6）

2026-09-17。ブランチ `garden-g6`、main は `4d7dd7a`（G0〜G5 と vm-0.5.1 merge 済み）。
著者がブラウザ（<https://sabiruby.github.io/rubevy_games/garden/>）で試遊して 3 つ書き留めた:
**夜が暗すぎる**、**ホイールのズームが 2 段階しか効かない**、**ゲーム内に説明が無い**。

3 つとも別の話に見えるが、作業してみると共通点が 1 つあった。**どれも「書いた機械の上では正しく見えていた」**。
夜の数字は lavapipe の窓で選んだのではなく想像で置いた数字で、ホイールは PC のマウスでしか触っていない
コードで、説明は「docs/garden.md に全部書いてある」で済ませていた。G6 でやったことの半分は直すことで、
もう半分は**確かめる道具を作ること**だった — 真夜中を撮る `--at`、カメラに自分の状態を喋らせる
`CameraLog`、フォントを本文から切り直す `tools/subset-font.sh`。以下その順で書く。

## 1. 夜 — 数字を動かす前に、真夜中の絵を安く撮れるようにした

`day_night`（`garden/src/main.rs`）は昼夜を 4 つの量で出している: 太陽（月）の
`DirectionalLight` の向き・色・`illuminance`、`GlobalAmbientLight` の色と `brightness`、
そして `ClearColor`。夜の値は

```rust
let (color, illuminance) = if night { (Color::srgb(0.55, 0.64, 1.0), 300.0) } else { … };
…
ambient.color = Color::srgb(0.35, 0.45, 0.8);
ambient.brightness = 30.0;
…
clear.0 = Color::srgb(0.03, 0.04, 0.10);
```

だった。**この数字が妥当かどうかは、真夜中の絵を見ないと決められない。** ところが真夜中は
`DAY_LENGTH = 60` 秒周期の位相 0.75、つまり起動から 40.2 秒後で、WSL には Vulkan ドライバが無いので
窓は docker + lavapipe（影付き PBR は 1 フレーム 1 秒近い）。`--shot p.png 40` を数字の組ごとに
待つのは、比較のやり方として成立しない。

なので先に `--at SECONDS` を足した。**動かすのは `Sky::shift` だけ**で、これは G3 が
「ファイルから読み戻した庭は保存された時刻から続く」ために作った時計そのもの。世界の他の部分
（草の成長も空腹も接触の記録も）は `Time::elapsed_secs()` を見ているので、**太陽だけが進む**。
`--shot` があるときは撮影の瞬間から逆算する（`shift = at - shot.after`）ので、
`--shot p.png 12 --at midnight` は「12 秒育った庭を、真夜中に撮った絵」になる。
`midnight` を名前で書けるようにしたのは、誰もが名前で頼む唯一の時刻だから
（`MIDNIGHT = (0.75 - DAWN_OFFSET) * DAY_LENGTH`。ここが本当に太陽の最下点かはテストで見ている —
式を目で確かめるより速い）。

### 2 つの数字は別の仕事をしている

`--at midnight` で古い値と新しい値を撮り比べて分かったのは、**`illuminance` と `brightness` は
別のものを直す**ということ。

* 月（`DirectionalLight`）が描くのは**輪郭**。生き物に明るい面と影の面ができ、木の幹に向きができる。
  これが無いと庭は「黒い板」に見える。
* 環境光（ambient）が埋めるのは**影の面**。木の下に立っている甲虫が存在するかどうかはこっちが決める。

月だけ上げると「上面だけ明るくて胴体が無い生き物」になり、環境光だけ上げると「全部灰色で平ら」になった。
両方要る。最終的に **月 300 → 400 lux、環境光 30 → 55**、色は両方少しだけ明るい方に、空も
`0.03,0.04,0.10` → `0.06,0.08,0.17`。

昼を触っていないのが効いていて、**庭でいちばん暗い昼**（地平線の太陽、1,200 lux・環境光 120）が
夜の 3 倍あるので、差は一目で読める。同じ切り出し（パネルが覆っていない x 690–1060, y 200–870）で
地面の平均輝度を測ると **18 → 26 / 255**、午後（`docs/garden.png`）は **81**。

絵は `docs/garden-night.png`。**前の絵は残していない**（指示どおり「後」だけ）。捨てる前に並べて見た
比較画像では、前は木のシルエットと影しか判別できず、後は草・ウサギ・甲虫・影が全部読める。

## 2. ホイール — 単位を読んでいなかった

著者の「2 段階しか効かない」は、計画書の推測どおり `MouseScrollUnit` の話だった。ただし
**推測を確かめる手段がその時点で無かった**ので、まずそこを作った（§4）。

Bevy の `MouseWheel` には `unit` が付いている。PC のマウスは winit 経由で `Line`、`y = ±1.0`
（1 ノッチ 1 行）。ブラウザは `Pixel`、`y` は `wheel` イベントの `deltaY` そのもので、Chromium の
実マウス 1 ノッチは **100**。元のコードは

```rust
orbit.distance = (orbit.distance - w.y * 2.0).clamp(12.0, 90.0);
```

で、1 ノッチが PC では 2 単位、ページでは 200 単位。範囲は 78 単位しかない。**2 段階**で、
2 段階目は `clamp` そのもの。

直し方は 2 段構え。まず単位をノッチに正規化し、次に**ノッチを引き算でなく比**にした:

```rust
fn notches_of(unit: MouseScrollUnit, y: f32) -> f32 {
    match unit { MouseScrollUnit::Line => y, MouseScrollUnit::Pixel => y / PIXELS_PER_NOTCH }
}
fn zoom_by(distance: f32, notches: f32) -> f32 {
    (distance * ZOOM_PER_NOTCH.powf(-notches)).clamp(ZOOM_MIN, ZOOM_MAX)
}
```

比にしたのは単位の話とは別の理由で、**引き算は距離 8 と距離 80 で同じ感触になりようがない**から。
近いところでは飛びすぎ、遠いところでは動かなすぎる。10% なら全域で同じ 1 段。範囲は
`ZOOM_MIN = 6.0`〜`ZOOM_MAX = 110.0`（従来は 12〜90。近づける側を広げたのは、1 匹を見るため）、
端から端まで `ln(110/6)/ln(1.1) ≈ 30.5` ノッチ。

**`PIXELS_PER_NOTCH = 100.0` は測って決めた定数**であって、規格ではない。ブラウザとデバイスで違う
（トラックパッドは 1 イベントが数ピクセル）。100 を置いたのは Chromium の実マウスがそうだからで、
トラックパッドでは 1 回のスワイプが細かい複数イベントになって連続的に効く — これは比のおかげで
そのまま自然に動く。**100 を置いてから実測した**ので、当たっていたというより「当たっていることを
確かめた」に近い（§4 のログに `y=100` がそのまま写っている）。外れていたら、直すのは定数 1 つ。

`notches_of` と `zoom_by` は純関数にしてテストを書いた（`garden/src/main.rs` の `mod tests`）。
**窓もブラウザも無いテスト環境では、このバグは絶対に現れない**ので、せめて「同じ指の動きが
両方の単位で同じノッチ数になる」ことだけは機械に見張らせる。

最初のテストは「端から端まで約 25 ノッチ」と書いて落ちた（実際は 30.5）。テストの数字を直した —
`ZOOM_PER_NOTCH` を触って 25 に合わせるのは、テストのために設計を曲げることになる。

## 3. パン — 4 つ目の数字

`Orbit` は `yaw` / `pitch` / `distance` の 3 つで、カメラは常に原点を見ていた。40×30 の野原で、
隅の甲虫は**振り向けるが行けない**。`focus: Vec2` を足し、`camera_at` が原点でなく `focus` を
基準に目を置くようにした。

決めることがあったのは**どのボタンか**だけ。左ドラッグは回転のまま（従来は左右どちらでも回転だった）、
右ドラッグと `Shift`+左ドラッグがスライド。右を選んだのは普通そうだから、`Shift`+左も足したのは
トラックパッドに右ボタンが無いことがあり、ブラウザが右をコンテキストメニューに使うことがあるから。
**ブラウザでは右ドラッグが効くことを実測で確認した**（winit の web バックエンドが pointer イベントで
`preventDefault` しているので、`web/garden.html` に足すものは無かった）。

ドラッグ量は足す前に `yaw` で回す（`ground_axes`）ので、カメラを回した後でも「画面の右」に滑る。
距離に比例させてあるので、近寄っていても寄っていなくても同じ感触。キーは WASD と矢印、`Home` で
4 つとも既定値に戻る。`focus` は野原の外 8 単位までで止める（`clamp_focus`) — 迷子になれる庭は庭でない。

`Orbit` に `PartialEq` を derive して「変わったときだけ `Transform` を書く」に変えた。以前は
`moved` フラグを手で立てていて、`Home` とキー入力が増えると分岐が増える一方だった。

## 4. ブラウザの中のカメラをどう読むか — `CameraLog`

ここが G6 でいちばん考えたところ。**wasm のキャンバスの中の `Orbit` を外から読む方法が無い。**
HUD には出していないし、`Transform` を問い合わせる口も無い。playwright にできるのは
「マウスを動かす」「console を読む」だけ。

なので `GARDEN_SELFTEST=1`（ページでは `?selftest`）のときだけ `CameraLog` という空のリソースを
挿し、`orbit_camera` がそれを見て喋るようにした:

* **ホイールのメッセージ 1 つにつき 1 行。** `unit` と生の `y` と、ノッチ数と、前後の距離。
  ここに `unit` を出しているのが肝で、**診断（「Pixel で来ている」）そのものがログに写る**。
* ドラッグ中は 0.25 秒に 1 行のサンプル（60 Hz で全部出すとログが使い物にならない）。

普通の実行では 1 行も出ない。ゲームであってログではないので。

検討して捨てた案が 2 つある。(a) HUD に距離を出す — 絵から読み取るのは OCR になるし、
playwright から数値として取れない。(b) 窓の自己テスト（`window_selftest`）にホイールの検査を足す —
**窓には転がすホイールが無い**（`MouseWheel` はプラットフォームから来るメッセージで、
`ButtonInput` のようにテストから押せない）。結局「窓では単体テスト、ブラウザでは実測」に落ち着いた。
窓の判定は 21 行のまま。

## 5. ゲーム内の説明 — 枠は共通、言葉はゲームごと

`H` と `?` で開閉（`Esc` で閉じる）、**起動直後に一度開いている**パネル。HUD には
`H: help / 操作説明` を、薄い灰色でなくキーの色（黄）で出した — 気づかれない案内は無い案内と同じで、
それがまさに著者の試遊が見つけたことだから。

枠は `crates/rubevy-arena/src/guide.rs`（窓・2 つのキー・2 言語の並べ方・フォント）、言葉は
ゲームごと。**言葉を 1 ファイルに集めたのは途中で作り直した部分**で、最初は `garden/src/window.rs`
と `sabibots/src/main.rs` の中に直接置いていた。著者が日本語を自分で直したいという話が来て、
`garden/src/guide_text.rs` と `sabibots/src/guide_text.rs` に丸ごと移した。
両方のゲームが出す文字列（HUD の `H: help / 操作説明` とパネル末尾の 1 行）だけが `guide.rs` に残る。

内容は「キー一覧を散文にしたもの」にはしないようにした。最初の 4 段落は**ページを開いた人が
実際に見ているもの**（草、空腹、1 分で回る昼夜、つがい）で、そのあとに**言われなければ絶対に
分からない 2 つ** — 頭脳が Rust 製 VM の上の Ruby で ECS のコンポーネントを名前で読んでいること、
生き物をクリックして Ctrl+Enter を押すと庭を止めずに種の全個体が入れ替わること。

### 絵を撮るときはパネルを閉じる

パネルは窓の中央にあり、`--shot` の絵の主役をちょうど覆う。**`--shot` があるときは既定で閉じた
状態で始まり、`--guide` を付けたときだけ開く**ことにした。`--shot p.png 10 --guide` が
「日本語が豆腐でない」を確かめる撮り方で、`docs/garden-guide.png` と `docs/battle-guide.png` が
その絵。

最初の絵ではパネルが**エディタと VM パネルの後ろに隠れていた**（両ゲームとも起動時に 3 枚開く）。
`egui::Order::Foreground` に変えた — 探さないと見つからない説明は説明ではない。
2 枚目の絵では**キー表が下で切れていた**ので `default_size([640.0, 820.0])` にした。
スクロールバーを探させるキー一覧は誰も読まない。

日本語の全角括弧「（）」は egui の CJK 組版では前後が大きく空いて見えたので、半角に直した。
これは好みの話なので、著者が戻すかもしれない。

## 6. フォント — 9.6 MB を 62 KB に

egui の既定フォントは Ubuntu-Light と Noto の**記号**フェイス 2 つで、**CJK は 1 文字も無い**。
落とす先も無い（ブラウザ版は wasm で機械のフォントに触れない）。なので同梱した。

Noto Sans JP（SIL OFL 1.1、google/fonts の `ofl/notosansjp`、`OFL.txt` をファイルの隣に置いた）。
配布物は **9,589,900 バイト**の可変フォント。バイナリに入るのは **62,780 バイト**:

1. `fontTools.varLib.instancer` で `wght=400` に固定（可変軸が 3.8 MB ある）、
2. `fontTools.subset` で**ガイドが実際に使う 327 文字**だけに絞る。

文字の集め方は「`guide_text.rs` 2 つと `guide.rs` の非 ASCII 文字すべて + 印字可能 ASCII 全部」。
ASCII まで入れているのは、`me[:Hunger]` を含む日本語の文が単語の途中でフォントを乗り換えないため。

egui への入れ方は **fallback**（`FontDefinitions::families` の `Proportional` と `Monospace` の
**末尾に push**）。egui は 1 文字ずつ順に探すので、既定フォントが持っている文字は今までどおり
既定フォントが描く。**エディタとパネルのラテン文字は 1 ピクセルも変わらない。**

入れる場所は `EguiPrimaryContextPass` の中で `Local<bool>` で 1 回だけ。`Startup` では駄目で、
主ウィンドウの egui コンテキストがまだ無く `ctx_mut()` が `Err` を返す。

### 本文とフォントは一緒に切る

サブセットは本文に合わせて切ってあるので、**本文を直したらフォントも切り直さないといけない**。
新しい文字は白い箱になる。`tools/subset-font.sh` がその手順そのもので、上の 3 ファイルから
文字を読み直し、フォントを取ってきて（引数でパスを渡してもよい）、切り直す。
`docs/garden.md` と両ゲームの `guide_text.rs` の先頭にそう書いた。これが**このやり方の唯一の
壊れ方**なので、「使ったフォントはこれです」というメモではなくスクリプトにした。

`instancer` は名前テーブルの刈り込みで family name を `Noto Sans JP Thin` にして残す
（`usWeightClass` は 400 に直っている）ので、スクリプトの最後で `Noto Sans JP Subset` に直している。
OFL は改変と同梱を許しているが、著作権と licence の name record は Noto のまま触っていない。

## 7. wasm の増分

著者判断（2026-09-17）で「日本語フォント分のサイズ増加は許す、サブセット化はする」。実測:

| | bytes（`wasm-opt -Os` 後） | gzip -9 |
|---|---|---|
| `garden/pkg/game_bg.wasm` G5 時点（sabiruby 0.5.1） | 35,216,938 | 10,715,122 |
| + カメラ（G6 の 2 つ目） | 35,217,417 | 10,716,945 |
| **+ ガイドとフォント（G6 の 3 つ目）** | **35,306,969** | **10,772,842** |
| `sabibots/pkg/game_bg.wasm` G5 時点 | 34,794,885 | 10,593,843 |
| **+ ガイドとフォント** | **34,884,167** | **10,649,110** |

**ガイドの増分は 1 ゲームあたり約 90 KB、うち 63 KB がフォント。** 残り 27 KB がパネルと
両ゲームの文字列と、egui のフォント機構が 2 つ目のファミリで引き込む分。gzip 後は 55 KB で、
サブセットした `glyf` テーブルがもう圧縮の余地をあまり持っていないため圧縮率は低い。
35 MB のモジュールに対して **0.25%**。フォントを丸ごと入れていたら 27% 増だった。

## 9. やっていないこと・迷った点

* **PC の窓でホイールを実際に転がしてはいない。** `MouseWheel` はプラットフォームから来る
  メッセージで、`ButtonInput` と違って自己テストから「押す」ことができない。`Line` 単位の側は
  単体テスト（`notches_of(Line, 1.0) == 1.0` と「10 ノッチで Pixel と同じ距離に着く」）で
  押さえた。窓の判定にホイールの行を足さなかったのはこのため（21 行のまま）。
* **`PIXELS_PER_NOTCH = 100.0` は Chromium の実マウスの実測値。** Firefox は `Line` で来るし、
  トラックパッドは 1 イベントが数ピクセル。後者は比のおかげで自然に効くが、
  **Firefox とトラックパッドでは確かめていない**（この機械にあるのは Chromium だけ）。
* **`--at` と `--load` を同時に渡したときは `--load` が勝つ**（`load_world` が `Sky::shift` を
  上書きする）。検査用の道具なので、そのままにして報告する。
* **日本語の文面は下書き。** 著者が自分で直す前提で、`garden/src/guide_text.rs` と
  `sabibots/src/guide_text.rs` の 2 ファイル（＋共通の 2 文字列が `crates/rubevy-arena/src/guide.rs`）に
  集めてある。直したら `tools/subset-font.sh` → `cargo build` → `web/build.sh all`。
* **全角括弧を半角に直した**のは egui の組版で前後が空きすぎて見えたからで、好みの範囲。
* 夜の数字は「真夜中の絵が読めるところまで上げ、それ以上は上げない」で決めた。
  **明るさを位相で連続に変える**案（夕方から真夜中に向けて滑らかに落とす）は採らなかった。
  いまの `night` は `height <= 0.0` の二値で、そこに連続量を持ち込むと `"night"` の publish と
  見た目がずれる可能性がある。夜の中での明暗は月の向きが動くぶんだけ既に付いている。
