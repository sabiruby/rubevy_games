## 2. F3-0b: 建てる依頼を自前のメッセージにした（コミット 2）

### 2.1 形

`build::Order { at: UVec2, what: Option<What>, dir: Dir }` — **場所・何を・向き**。1 つの system
だったものが 2 つに割れた:

* `build::clicks`: `WorldClick`（共有 crate のもの。世界の点しか持っていない）と `Hand` から
  `Order` を作る。**何も建てない。**
* `build::orders`: `Order` を読んで建てる。**マウスも手も知らない。**

判定は `Order` を直接書く。`Hand` も `WorldClick` も触らない。

### 2.2 順序の 1 行は残ったが、理由が変わった

F2 が書いた `selftest.before(build::clicks)` の理由は「判定が同じフレームに `Hand` と
`WorldClick` を書き、答える側が**走ったときの** `Hand` を読むので、順番次第で
**前のフレームのメッセージを今のフレームの手で**建てる」だった。**その穴は構造ごと無くなった** —
依頼が「何を」を持っているので、誰がいつ走っても建つものは同じである。

残るのは**判定という仕事の性質**で、建てることの性質ではない: 判定は N フレーム目に依頼を書き、
N+1 フレーム目に結果を見る。だから毎フレーム `build::orders` の同じ側にいなければ 1 フレーム
早く見てしまう。1 行は残し、**名指しを `clicks` から `orders` へ**変えて（マウスが何をするかは
もう判定の関心ではない）、理由をコードのコメントに書き直した。

**「1 フレームに 1 タイル」も理由が変わった。** F2 はそうしないと壊れたので規則だったが、今は
5 つの依頼を同じフレームに書いても 5 つ別のものが建つ。それでも 1 タイル 1 フレームのままに
したのは、**log がどのタイルで失敗したかを言う**からである（コメントに書いた）。

## 3. F3-1: インサータ — 語と、`move` の待ち方（コミット 3）

### 3.1 DSL の語と、なぜその形か

計画 §3.3 の案（`behind` / `front` / `move` / `idle` / `wants?`）を、garden の prelude の作法
（`def run`、オブジェクトのメソッド、`Rubevy::Proxy`）に照らして決めた。**決めた語は 9 つ**:

| 語 | 何か | 費用 |
|---|---|---|
| `inserter "名前" do … end` | クラスを作る。garden の `creature` と同じ形 | — |
| `def run` | 本体。`run_inserter` が呼ぶ | — |
| `behind` | 後ろのタイルが出せる物の**名前（Symbol）**、無ければ nil | tick の中。0 フレーム |
| `holding` | 手の中の物の名前、無ければ nil | 同上 |
| `front_takes?(item)` | 前のタイルが今それを受け取るか | 同上 |
| `move` | 腕を振る。**振り終わるまで返らない**。置けたら true | 1 回の swing |
| `idle` | 1 swing ぶん眠る | swing |
| `swing_seconds` / `items` | `data.rb` が言う数と名前の一覧 | 0 |
| `log` | ログ 1 行 | 0 |

**`front` を「オブジェクト」にしなかった理由**: 案は `front.accepts?(thing)` だが、tick の中で
答えるクロージャは `Vm` を持てず**平たい `Answer` しか返せない**（rubevy `host-api.md`）ので、
`front` は作れない。`front_takes?(item)` は同じことを 1 往復で言う。

**`move` が引数を取らない理由**: 案は `move thing` だが、腕が持っていくのは「後ろにある物」で
あって引数ではない。引数を取ると**嘘をつける口**になる（別の物を渡しても後ろの物が動く）。
`behind` と `move` が同じフレームの同じ世界を見る（§3.4）ので、引数は情報を足していない。

**`wants?` は prelude の語ではない。** 既定のスクリプトが `def wants?(item) = true` を定義し、
`run` がそれを呼ぶ。プレイヤーが最初に書き換えるのはそこ、という形にした（計画の案どおり）。

**著者が変えたければ**: 語は `factory/ruby/prelude.rb` の中（`Inserter` のメソッド名）で、
そこを変えれば既定のスクリプト `factory/ruby/inserter.rb` と一緒に動く。ゲームの Rust が
名指ししているのは**問いの名前**（`factory.behind` など）と `run_inserter` だけ。

### 3.2 `move` の待ち方 — 3 案を比べて (a) を選んだ

計画 §3.3 が挙げた 3 つを、**「機械が撤去された」「スクリプトが差し替えられた」「腕の途中で
セーブされた」でどうなるか**で比べた。

| | (a) `Request` を持ち続ける | (b) イベントを待つ | (c) `sleep` してから確かめる |
|---|---|---|---|
| ゲームが Ruby に教える数 | **無し** | 無し | **swing の長さ**（両側に同じ数が要る） |
| 撤去されたとき | エンティティごと消え、`Arms::waiting` の行も消える。タスクも `ScriptTask` と一緒に終わる | 購読が閉じて `Rubevy::Unsubscribed` が上がる（prelude に rescue が要る） | 何も起きない。眠ったまま起きて、起きた先に腕が無い |
| 差し替えられたとき | 古い request は 1 回答えられうるだけ（rubevy `tests/replace.rs`） | 同上 + 購読の後始末 | 同上 |
| 腕の途中でセーブ | 腕の状態は**格子**にある（`held`・`work`・`swinging`）ので保存できる。タスクの途中は保存できないが `run` は頭から始め直せる | 同じ | 同じ |
| 台数ぶんの持ち物 | request 1 つ（HashMap の 1 行） | **購読 1 本 + キュー**（既定 64 件ぶんの器） | 無し |

**(a) を選んだ。** 決め手は 2 つ:

1. **(c) は同じ数を 2 か所に置く。** Ruby が `sleep swing_seconds` して確かめる形だと、
   腕の長さが Rust と Ruby の両方にあり、片方を変えるともう片方が黙ってずれる。
   `docs/numbers.md` の規則（数は 1 か所、出どころつき）に真正面から反する。
2. **(b) は台数ぶんの器を要求する。** 購読 1 本につきキューが 1 つで、1000 台なら 1000 本。
   rubevy の実測（`host-api.md`「How much a queue holds」）は「数値なら 1 本 16〜21 B × limit」
   だから壊れはしないが、**1 台 1 メッセージしか要らない**ものに 64 件の器を配るのは、
   あとで `limit: 1` という**出どころの無い数**を書くことになる。

(a) の弱点は「ゲームが request を持ち続ける」こと。持ち場所を **`Arms::waiting`（タイル →
request）**にしたのが答えで、撤去は「格子からタイルが消える」→ `keep_the_crew` が
`arms.forget(tile)` する、の 1 本道になる。実測でそれを確かめた（判定
`an inserter taken away leaves no script behind`: 4 本 → 3 本、待ちは 0）。

**rubevy に何があれば楽だったか**（報告に出す。rubevy には書き込まない）は §7 に。

### 3.3 腕は Rust、状態は**格子**に

`What::Inserter` は 1 タイルの建物（向きあり）。腕の状態は `Building` の既にあるフィールドに
乗せた: `held` が手（1 個）、`work` が swing の途中、新しい `swinging` が「渡っている最中か」。
**component ではなく格子**にしたのは 3 つとも同じことを言っている:

* セーブは格子である（F5）;
* 工場の 1 歩（`belts::step`）は `App` を持たないので、**腕の単体テストが Bevy 無しで書ける**;
* 「何も作られず何も失われない」の和は格子を歩く（F2a の 5 分のテスト）ので、
  **手の中の物が自動的に数に入る**。

`swinging` を `held` の有無で代用しなかったのは、「手が塞がっていて止まっている腕」
（前が受け取らなかった）と「渡っている最中の腕」が**違う状態**だから。

### 3.4 フレームの順番 — これが全部の土台

```
build::orders → keep_the_crew → RubevySet::Deliver → Tick（3 つの問いはここで答える）
  → RubevySet::Answer（move が始まり、後ろの物を手に取る）→ FactorySet::Step（工場が動く）
```

`items::run_the_factory` に `.after(RubevySet::Answer)` を足した。これで
**スクリプトが見た世界が、その腕が持ち上げた世界**になる（間に何も動かない）。
計画 §5 の「同じ tick で書いた component は読めない」に当たる問題は、状態が Resource（格子）で
あり、読む側が `answer_in_tick`（Tick の世界）、書く側が Answer と Step なので起きない。

### 3.5 ベルトと機械の直結を外した

`machines::hand_to` に `Offer`（`Direct` / `Inserter`）を足し、**機械はインサータの手からしか
受け取らない**。`machines::deliver`（機械 → 前のタイル）は**消した** — 機械から出るものは
インサータが取る。

**ベルト → 箱と、採掘機 → ベルト/箱 は今のまま**にした。理由:

* Factorio は箱にもインサータを要求するが、**それを写すと F1 の線（採掘機・ベルト・箱）が
  Ruby 無しでは建たなくなる**。ゲームを開いて最初に建てるものと、判定の最初の線が、
  この段階の主題（インサータ）に巻き込まれる。
* 採掘機がベルトに直接出すのは **Factorio もそう**で、箱に直接出すのもそう。
* 「Ruby が要る線」は**機械の線**であるべきで、それがこのゲームの主題である。

**副作用が 1 つ**: 機械の `dir` が**何も言わなくなった**（出口を言う人がいなくなった）。
`Data::output_of` を消した。Factorio の組立機にも向きは無いので、これは写しとして正しい。

### 3.6 `idle` のずらし方 — 数を足さずに

**`idle` は `swing_seconds` 眠る。** 別の数ではない理由: 詰まっていない腕は `idle` に来ない
（`behind` が何かを返し続けるので `move` が回る）ので、`idle` の長さは**飽和時の能力に影響
しない**。効くのは「止まっていた線に物が来てから気づくまで」だけで、その粒度は腕自身の粒度
（1 swing）と同じにするのが自然。**より短くすると 1000 台ぶんの命令を何も無いことに使う**。

**ずらしは位相を 1 回だけ散らす**: `run_inserter` が `srand(me.to_i)` して
`sleep swing_seconds * rand` を 1 回。garden の `srand(being.me.to_i)` と「最初のひと呼吸」
（`sleep 0.05`）の両方の先例に乗っている。**新しい数は 1 つも足していない。**
以後は各台が自分の仕事の都合で位相がずれるので、戻って揃うことはない。

### 3.7 壊れたスクリプト — 行が取れるのは Ruby の中だけだった

**測って分かったこと**: `ScriptEnded` が届いた時点で `ScriptWorld::stats` は
`frames=[] location=None finished=true` を返す。**終わったタスクにはフレームが残っていない。**
だから「ゲームがバックトレースから行を読む」道は無い。

代わりに **prelude の `rescue` が行を出す**: 例外はまだバックトレースを持っているので、
`Inserter.said_at(e)` が `inserter.rb:4` を作り、`Task.current` の `@broke_at` に置く。
ゲームは `ivar_get` 1 回でそれを読む（garden が `@being` / `@memory` を読むのと同じ道）。

そのために **prelude は自分の長さを知る必要がある**。`names_and_numbers` に
`def self.prelude_lines` を足し、`compile` が `Program::new` を**2 回**呼んで出す:
前置きブロックの行数は**中身の数字に依らない**（各項目が 1 行）ので、
「prelude だけの `prelude_lines` + ブロックの行数」が答えになる。単体テストがその不変を見る。

`Task::Overrun` は `Exception` で `rescue => e` に掛からないので、**その場合だけ
`inserter.rb:?`** になる。rustdoc に書いた。

最初に書いた版はバックトレースの行を `split(":").last` で取っていて `"in run"` を拾っていた。
実測（`TEMP backtrace=["inserter.rb:208:in run", …] prelude_lines=204`）で分かり、
「コロンで割った中で**最初に整数になる**もの」に直した。
