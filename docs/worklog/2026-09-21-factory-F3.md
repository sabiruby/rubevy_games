### 1.1 `data::line_of` が消えた

F2 は「宣言をまたぐ検査に言える行が無い」ので**ソースを引いて行を探す** 20 行を書いていた
（`data::line_of`、計画書 §7 の 09-21 F2 の 1 行目）。`take_with_lines` が返す
`Declared { name, value, line }` の `line` がそれを置き換える。消えたもの:

* `line_of` そのもの（20 行）と、それを呼ぶ 6 か所;
* `tables_of` と `exactly_one` の `source: &str` 引数（`read_the_declarations` の中で

`Declared` は `#[non_exhaustive]` なので、分解するパターンには `..` が要る
（`for (i, Declared { name, value: decl, line, .. }) in machines.into_iter().enumerate()`）。
sabiruby の担当が報告に書いていたとおりで、当たったのはこの 3 か所だけだった。

### 1.2 **期待値は 1 つではなく 2 つ動いた**

sabiruby の §5 の 2 は「`a_machine_gives_one_picture_for_each_tile_it_covers` の後半が
`Some(4)` → `Some(5)`」と 1 件を名指ししていた。実際に建てて回したら、**もう 1 件落ちた**:

```
---- data::tests::a_mistake_in_a_declaration_says_which_line_it_is_on stdout ----
assertion `left == right` failed: data.rb:5: iron_plate has coal in it and nothing declares an item called that

```

同じ理由（`GOOD` のレシピは 4 行目と 5 行目に跨り、`line_of` は「始まる行」= 4、
`Declared::line` は「終わる行」= 5）で、**表の中の 1 ケース**なので名指しの数え落としである。
数え落としは害が無い（テストが落ちて場所を教える）が、**「1 件だけ落ちる」と書かれたものが
2 件落ちた**ことは記録しておく価値がある: 「宣言をまたぐ検査」は 6 か所あり、そのうち
`GOOD` の 2 行に跨るレシピを指すものが 2 つあった。

**揃ったことが直った証拠**である。同じ宣言について
`a_declaration_over_two_lines_is_reported_at_the_second`（serde が断る道）と
`a_machine_gives_one_picture_for_each_tile_it_covers` の後半（games が断る道）と
上のケースが、**3 つとも 5 と言う**。F2 はこの 3 つが 5・4・4 だった。

## 2. F3-0b: 建てる依頼を自前のメッセージにした（コミット 2）

計画書 §7 の 09-21 F2 の行（「クリックに『何を持っていたか』が載っていない」。本体が原則から
決めて「F3 の最初に」と指定）。

### 2.1 形

`build::Order { at: UVec2, what: Option<What>, dir: Dir }` — **場所・何を・向き**。1 つの system
だったものが 2 つに割れた:

* `build::clicks`: `WorldClick`（共有 crate のもの。世界の点しか持っていない）と `Hand` から
  `Order` を作る。**何も建てない。**
* `build::orders`: `Order` を読んで建てる。**マウスも手も知らない。**

判定は `Order` を直接書く。`Hand` も `WorldClick` も触らない。

### 2.2 順序の 1 行は残ったが、理由が変わった

F2 が書いた `selftest.before(build::clicks)` の理由は「判定が同じフレームに `Hand` と
`WorldClick` を書き、答える側が**走ったときの** `Hand` を読むので、順番次第で
**前のフレームのメッセージを今のフレームの手で**建てる」だった。**その穴は構造ごと無くなった** —
依頼が「何を」を持っているので、誰がいつ走っても建つものは同じである。

残るのは**判定という仕事の性質**で、建てることの性質ではない: 判定は N フレーム目に依頼を書き、
N+1 フレーム目に結果を見る。だから毎フレーム `build::orders` の同じ側にいなければ 1 フレーム
早く見てしまう。1 行は残し、**名指しを `clicks` から `orders` へ**変えて（マウスが何をするかは
もう判定の関心ではない）、理由をコードのコメントに書き直した。

**「1 フレームに 1 タイル」も理由が変わった。** F2 はそうしないと壊れたので規則だったが、今は
5 つの依頼を同じフレームに書いても 5 つ別のものが建つ。それでも 1 タイル 1 フレームのままに
したのは、**log がどのタイルで失敗したかを言う**からである（コメントに書いた）。
