# 名前の整理 — `reflex` は `on` に、「頭脳」は「行動アルゴリズム」に（G7）

2026-09-17。ブランチ `garden-g7`、main は `60e65f4`（G6b merge 済み + 計画書の G7 節）。
著者の判断は 1 行で言える: **デモは初見の人がピンとくる名前であるべき**。
`reflex(:hit)` は自分たちが作った語彙で、`on(:hit)` はもう知っている語彙。
「頭脳」は比喩で、「行動アルゴリズム」は中身そのもの。

やることが決まっているぶん、この段階の難しさは「どこまでを名前と呼ぶか」にある。
以下、置換の範囲をどう切ったか、機械的にやってどこで手が要ったか、
そして絵とフォントが**文面に連動して古くなる**という G6 から続く事情の続きを書く。

## 1. 置換の範囲 — 3 本の線を引いた

`grep -rn reflex` は worklog と plans を除いて 14 ファイル、`brain|mind|頭脳` は 23 ファイルに出る。
全部を一様に置換すると Rust の `struct Mind`、`Res<Brains>`、`watch_minds`、`give_mind` まで
巻き込む。計画書の 2 項が挙げている置換先は
「`guide_text.rs` ×2、`docs/garden.md`、`docs/sabiruby-battle.md`、README の利用者向け記述、
HUD/エディタのラベル」で、**識別子は入っていない**。1 項の `reflex` だけは
「内部名も揃える」と明記されている。そこで 3 本の線を引いた。

1. **`reflex` は全部**。DSL の呼び名（`on`）、機構の名前（`handler`）、Rust の型・フィールド・
   システム名、`ask` の種別、ログと selftest の文言まで。旧名は残さない。
2. **`brain`/`mind`/「頭脳」は、人が読む文字列だけ**。ガイドの文、HUD とエディタのラベル、
   docs、README、ランディングページ、そして**ゲーム内エディタに出るファイル**
   （`garden/ruby/creatures/*.rb`、`sabibots/ruby/robots/*.rb`）のコメント。
3. **識別子と、識別子を説明している散文は触らない**。`Mind`、`Brains`、`brain: Option<String>`、
   `watch_minds`、`give_mind` と、それらを名指ししている Rust/Ruby のコメント。

2 と 3 の境目は「その文字列が画面に出るか」。`prelude.rb` はエディタに出ない
（エディタが開くのは種のファイルで、prelude は前に連結されるだけ — `prelude_lines` の
オフセットがそのため）ので 3 に入れた。一方 `beetle.rb` の `# --- the brain ---` は
`docs/garden.png` に**写っていた**ので 2 に入れた。この線引きの結果、
`grep` に残るものは報告に全部並べてある。

## 2. 機械的な置換と、手で直した 6 か所

Ruby と Rust は sed の並びで一度に通した。順番が要る:

```
s/\breflex(:/on(:/g      # DSL の呼び出しが先。後だと handler(:hit) になる
s/REFLEX_SLOTS/ON_SLOTS/g
s/def self\.reflex(/def self.on(/
s/reflexes/handlers/g    # 複数形が先。後だと handlers が handlerses になる
s/reflex/handler/g
```

これで `ON_SLOTS`、`__handler_N`、`run_handler`、`start_handlers`、`Rubevy.ask("handler", …)`、
`ReflexTest` → `HandlerTest`、`reflex_runs` → `handler_runs` までが一度に揃う。
`git diff` を全部読んで、機械が間違えた 6 か所を直した:

* `docs/worklog/2026-09-16-reflex.md` — **ファイル名は歴史**。`prelude.rb` と `docs/garden.md`
  からの参照が `2026-09-16-handler.md` になっていた。戻した。
* `` # One task per `reflex` `` — ここの `reflex` は機構ではなく **DSL の語**。`handler` ではなく
  `on` が正しい。両方の prelude で直した。
* `` how many `reflex`es the brain registered `` — `` `handler`es `` は英語ではない。
  「how many handlers」に書き換えた。
* `"{} reflex(es); …"` — HUD の hover。`handler(es)` ではなく `handler(s)`。
* ``a `reflex(:ate)` woken`` → ``an `on(:ate)` woken``。冠詞が変わる。
* `# --- the brain ---` の罫線。`brain` → `behaviour` で 4 文字伸びて、上の
  `# --- the handlers: … ---`（78 桁）と揃わなくなった。`-` を 4 つ削った。

最後の 2 つは、**置換は語の長さも変える**という当たり前のことで、
罫線と表の桁が揃っている文書ほど機械的な置換のあとに目で見る必要がある、という話でもある。

`docs/garden.md` と `docs/sabiruby-battle.md`（合わせて 2,100 行、`reflex` 79 件、
`brain`/`mind` 79 件）は python で、識別子（`` `Mind` ``、`` `Brains` ``、`watch_minds`、
`give_mind`、`Mind::asked_frame`、`` `Reflect` ``、worklog のファイル名）を先に退避してから
単語境界付きで置換し、戻した。`Reflect` が `Reflex` の置換に巻き込まれないのはこの退避のため
（実際には `s/Reflex/Handler/` は `Reflect` に当たらないが、退避したほうが読んで安心できる）。
手で書き直したのは `brainless creature`（→ `a creature with no behaviour`）と
`file-brained`（→ `running their file`）の 2 語で、どちらも `brain` を名詞以外に使っていた。

## 3. ガイドの段落 — 3 点を英日で

計画書 3 項が指定した 3 点は、どれも「反射」という比喩では言えていなかったことだ:

1. `on` のブロックは**行動アルゴリズムの `run` とは別のタスク**
2. **出来事が届いた瞬間に走る。中で `sleep` しても `run` は止まらない**
3. **動いている間は操作を預かる**

G6b の段落は 1 と 3 は言っていて、2 の後半（`sleep` しても `run` は止まらない）を言っていなかった。
これは「別のタスク」という言葉が実際に何を意味するかそのもので、mruby-task を使う理由でもある。
両ゲームの `guide_text.rs` に英日で足した。日本語は
「反射」→「イベントの処理」、「頭脳」→「行動アルゴリズム」以外は語順も語尾も変えていない
（**それ以外の日本語の表現は著者が後で調整する**、という指示のため）。

キー表は計画書の指定どおり短縮した。`編集した頭脳を種の全個体に適用` → `編集した行動アルゴリズムを適用`。
「種の全個体に」を落としても情報は消えていない — すぐ上の段落が
「その種の全個体が新しい行動アルゴリズムに入れ替わります」と言っているからで、
表は**キーと動作の対応**、段落は**その動作が誰に及ぶか**、と役割が分かれた。
英語側も同じに短くした（`apply the edited behaviour`、`write the behaviour to its file`）。

**英文に `reflex` を 1 か所だけ残してよい**という許可（`on` の意味を説明するため）は使わなかった。
段落が「一つの出来事を待ち受け、届いた瞬間に走る」と動作で言っているので、
比喩をもう一度出す必要がない。残った `reflex` は 1 件、`docs/README.md` の
worklog 行の `` building `on` (called `reflex` then) `` だけで、これは
**ファイル名が `2026-09-16-reflex.md` である以上、目次が嘘をつかないための橋**。

## 5. 絵 — 文面に連動して古くなるのは 4 枚ではなく 7 枚だった

指示は「ガイドの 4 枚と、古い語が写っている他の絵（`docs/garden.png` の HUD？）」だった。
HUD には出ていなかったが、**エディタのパネルに出ていた**。`--shot` はエディタを開いた状態で
撮るので、`docs/garden.png`・`docs/garden-night.png`・`docs/vm-inspector.png` の 3 枚が
`reflex(:night)` `reflex(:hit)` を大写しにしていた。ガイドの 4 枚と合わせて 7 枚撮り直した。

これは G6 で「日本語を足したらフォントを切り直す」を仕組みにしたのと同じ形の問題で、
**ゲームの文字列を変えると、それを写した絵が古くなる**。フォントはスクリプトが検出できるが、
絵は検出できない。今回は `git grep` ではなく**絵を 1 枚ずつ開いて読んだ**のが唯一の方法だった。

`docs/vm-inspector.png` だけは秒数を 8 → 14 にした。8 秒の絵ではレジスタが
`target NilClass / threat NilClass / heading NilClass` で、
隣の段落が「`target`、`threat`、`heading` の**クラスと値**が出る」と言っているのに
値が全部 nil だった（前の絵は `Contact` と `-0.59` が入っていた）。
10・12・14 秒を撮って、14 秒のものが `target Contact` と `heading -1.23` を持っていたので採った。
**文と絵が食い違うのは、絵を撮り直したときに一番起きやすい**。

## 7. 決めなかったこと

* **`prelude.rb` のコメントの `brain`**（sabibots 7 件、garden 7 件）。ゲームには出ないので
  §1 の線では 3 に入るが、DSL の説明文としては人が読む。計画書の列挙に無いので触っていない。
* **Rust の識別子**（`Mind`、`Brains`、`brain: Option<String>`、`give_mind`、`watch_minds`、
  `KeptBrains`）と、それを名指しする Rust のコメント。`docs/garden.md` の
  「`Mind` は登録していない」のような**識別子を説明している文**も、識別子のままにした。
* **`sabibots/Cargo.toml` の `description`**（`robots whose brains are Ruby`）。
  パッケージのメタデータで、計画書の「README の利用者向け記述」には入らないと読んだ。
