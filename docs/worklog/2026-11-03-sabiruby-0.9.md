# SabiRuby 0.9 と rubevy 0.4 — 依存のバージョンだけ

2026-11-03。SabiRuby の `docs/plans/release-0.9-plan.md` の R6（下流のバージョン上げ）。著者の判断（2026-11-03）で進めた。
先頭は main の `cbaa9ba`。手順は 0.8（`2026-10-19-sabiruby-0.8.md`）と同じだが、今回は rubevy（main `341db82`、0.4.0）と
sabiruby-playground（main `0e93e4e`、`SABIRUBY_REF` = v0.9.0）を**先に push してから**この repo を上げたので、一時的な `[patch]` は要らず、
`Cargo.lock` も同じコミットに入れた。

## 1. 変えたもの

- `Cargo.toml` の 3 行: `sabiruby "0.8"→"0.9"`、`sabiruby-compiler "0.5"→"0.6"`、`sabiruby-serde "0.4"→"0.5"`。コメントの
  「0.8 goes with rubevy 0.3」を「0.9 goes with rubevy 0.4」に（0.9.0 は VM に足すだけのリリースで、minor を揃えるのは VM を 1 つにするため）、
  compiler の「0.5 is the one of a 0.8 VM」を「0.6 is the one of a 0.9 VM」に。rubevy と rubevy-build は git のまま。
- `Cargo.lock`: `cargo update -p rubevy -p rubevy-build`（git の rubevy `3525007 → 341db82`、`sabiruby v0.8.0 -> v0.9.0`、
  `sabiruby-compiler v0.5.0 -> v0.6.0`、`sabiruby-serde v0.4.0 -> v0.5.0`）。`cargo tree -i sabiruby -e normal` は `sabiruby v0.9.0` が 1 つ、
  `cargo tree -d` に `sabiruby` の行は無い。
- `.github/workflows/pages.yml` の `PLAYGROUND_REF` を `2acc616` → `0e93e4e`（`docs/web.md` の「Three pins」の手順どおり。
  playground の `wasm/src` と `web/` は `2acc616` と同じ）。
- `docs/web.md` の三つのピンの表の「today `sabiruby 0.8.0`」を `0.9.0` に。

ゲームのコードは 1 行も変えていない。

## 3. 迷った点

- **lock を別のコミットにするか**: 0.7・0.8 では rubevy が push 前だったので別にした。今回は rubevy を先に push したので、建つ lock を最初から書けた。1 つのコミットにした。
