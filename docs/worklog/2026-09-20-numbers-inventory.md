## 1. なぜ機械で拾ってから目で選んだか

`garden/src/main.rs` は 6,292 行ある。「目で読んで数を拾う」を 6,000 行に対してやると、
**拾い落としが起きたことに誰も気づけない**。落とした数を数えられないからだ。
そこで順序を逆にした: まず `grep` で「数値リテラルを含む行」を全部拾い、その行数を記録し、
そこから目で落としていく。落とした数 = 拾った行数 − 選んだ件数 になり、
「8 割落とした」と書けるし、落とした基準を書く義務も生まれる。

拾った式は 2 本。

```
const:     grep -nE '^\s*(pub\s+)?const\s'
リテラル:  grep -nE '(^|[^A-Za-z0-9_.":])[0-9]+(_[0-9]+)*(\.[0-9]+)?'
```

リテラルの方の `[^A-Za-z0-9_.":]` は、`Vec2`・`f32`・`srgb`・`0.5` の `.5` のような
**識別子や小数の途中の数字**で行が二重に引っかかるのを避けるためのもの。
`"` を除いたのは文字列の中の数（`"sprites/tankRed_barrel1_outline.png"`、`"H: help"`）を外すため。
そのうえで `grep -vE ':\s*//'` でコメントだけの行を落とした。

結果:

| どこ | `const` 宣言 | リテラルを含む行 |
|---|---|---|
| `crates/rubevy-arena/src` | 20（うち数値 17） | 149 |
| `garden/src` | 88（うち数値 68） | 538 |
| `sabibots/src` | 28（うち数値 21） | 322 |
| `garden/ruby` + `sabibots/ruby` | 8（`NAME = 数`） | 237 |
| **合計** | **136（数値 106）** | **1,246** |

「数値 106」は型が `&str` でも `bool` でもない `const`。残りの 30 はファイル名・ラベル・
`CHECKS_EXIT_WHEN_DONE` のような真偽値で、数ではないが 2 つだけ一覧に入れた
（`localStorage` の接頭辞 `"garden:"` / `"sabibots:"`。計画書 §5 が「変えると利用者のセーブが消える」と
名指ししているので、不変量として挙げる価値がある）。

## 2. 何を落としたか、なぜ落としたか

1,246 行から 260 件。**約 8 割を落とした。** 基準は `docs/numbers.md` §0 に 9 つ書いたが、
書きながら決まったものが 3 つあるので、その経緯を残す。

**添字とスロット番号を落とし、スロットの「個数」は入れた。** `when 0 then __handler_0` の 0 は
数ではなく名前の一部だが、`ON_SLOTS = 7`（`garden/ruby/prelude.rb:357`）は**上限**で、
超えるとハンドラが黙る。同じ「7」でも仕事が違う。`EVERY_SLOTS = 4`、`REGS_FRAMES = 6` も同じ扱いにした。

**配列の長さを落とし、上限として効く長さは入れた。** `[Species; 2]` は種が 2 つあるという事実の言い直しだが、
`TEAMS: [(&str, &str, &str); 4]`（`sabibots/src/main.rs:54`）は `TEAM_COLORS` と長さが揃っていないと
`min(len - 1)` で色が潰れるので、揃っていること自体が不変量。`Brains` の 3 枠（`garden/src/main.rs:820`）も同じ。

**selftest の「段取り」を落とし、「閾値」は入れた。** `test.at = now + 0.5` は台本の間合いで、
0.5 を 0.6 にしても判定は変わらない。一方 `dot < 0.7`（`garden/src/main.rs:5693`）は
**判定そのもの**で、動かすと通る/落ちるが変わる。この線引きで selftest から 28 件が残った。
迷ったのは `main.rs:1101-1102` の「壁が隅で終わる」の誤差 0.01 で、ε は落とす基準に入れたのに
これは判定の本体でもある。入れたうえで、ε だと注記した。

落とした中でいちばん多かったのは **色の成分**。`Color::srgb(0.62, 0.66, 0.72)` は 1 行に 3 つ数があり、
共有 crate と 2 本のゲームを合わせると 100 行を超える。1 行 1 数の規則どおりに書くと一覧が色で埋まって
読めなくなるので、**色は 1 組 1 行**にまとめ、その旨を §0 に書いた。これは「落とした」ではなく
「数え方を変えた」なので、§6 の集計の注にも書いた。

PRNG の混ぜ定数（`0x9E37_79B9_7F4A_7C15` ほか、splitmix64）も落とした。これは調整値ではなく
アルゴリズムの仕様で、変えるのは「別の乱数にする」ことであって「値を選び直す」ことではない。

## 5. 分類でいちばん迷ったこと

`docs/numbers.md` §8 に 10 件挙げたが、性質の違う 3 つの迷い方があった。

**(a) と (b) の境**（半径、`UNSET`、9 色）。「変えると壊れる」の「壊れる」が何を指すかで変わる。
コンパイルが通らなくなる（`ON_SLOTS` を減らす）なら明らかに (a) だが、
「測って得た保証が消える」（9 色のコントラスト）や「見た目と当たりがずれる」（生き物の半径とモデルの倍率）は
壊れるのか調整なのか決めきれない。**壊れ方を 1 行書けるものだけ (a) にする**という線を引いた。
9 色は (c) にしたうえで「(a) 寄りの (c)」と注記した。

**(b) と (c) の境**（`TOUCH_REACH`、新しい芽の最小間隔、闘技場の半径）。
「遊びの数」と「動かす側の数」は、**Ruby に受け口があるかどうか**で実務上は決まってしまう。
`garden.rules` が今受けるのは 5 つだけ（`main.rs:4446`）なので、`TOUCH_REACH` を (b) にすると
「受け口を 1 つ増やす」という設計変更が要る。受け口の有無で分類を変えるのは筋が悪いので、
**あるべき置き場で分類し、「今変えられるか」の欄に現状を書く**ことにした。

**(e) をどこまで広げるか。** `--headless 10.0` は引数で変えられるので (e) だが、
**既定値の 10.0 そのものは変えられない**。厳密に取ると引数のある数は全部「既定値 (c)」＋「値 (e)」の
二重になり、件数が意味を失う。1 件として (e) に寄せ、§8-8 に迷いを書いた。

## 6. 数え直し

最初に集計を書いたとき、表を目で数えて 212 件と書いた。書いたあとで表を機械で数え直したら
**260 件**で、分類ごとの内訳も出どころごとの内訳も全部ずれていた。目で数えた数を文書に残すところだった。

数え直しは、この文書の Markdown の表をそのまま読んで、
行ごとに分類 `(a)`〜`(e)` と出どころの印（`**測った**` / `**導出**` / `**引用**` / `*理由のみ*` / `**不明**`）を
拾うスクリプトでやった（スクラッチパッドに置き、repo には入れていない）。
最初に走らせたとき **39 行が「出どころの印が無い」**と出た。内訳は:

* `§4.1`（Battle の機体模型 20 行）に**出どころの欄が無かった**。節の前書きで「全部 *理由のみ*」と
  済ませていたが、計画書は「各々に出どころ」と言っている。列を足し、名前の付いた 13 個は *理由のみ*、
  名前も付いていない 6 個（弾の寿命、砲口の位置、グリップ…）は **不明**に分けた。
  前書きで一括りにしていたら、この 6 個が不明だということが数えられなかった。
* 「同上」「上記」「元は `DAY_LENGTH`」のように**他の行を指しているだけ**の欄が 12 行。
  指し先の印を書き写した。
* 表記ゆれ 7 行（`**測って決めた**`、`**導出＋測った**`、`**値の出どころは不明**`）。印を揃えた。

さらに、機械で数えて初めて**同じ数を 2 行に書いていた**のが 2 件見つかった

**集計の数はすべてこのスクリプトの出力で、手で書いた数は 1 つも無い。**
（「毎フレーム 103 件」も同じ表の ● 印を数えたもの。● を付けたのは目視なので、
