## 2. `map_tiles` の下限を導出に置き換えた（コミット 2）

計画書 §7 の 09-21 F1 の行（「本体が原則から決めた: 導出に置き換える」）。F1 は
`settings.number("map_tiles")….max(8.0)` と書いて `numbers.md` §9.4 に「不明」と載せていた。

**導出を本当に確かめた結果、本体の見積もりとは 1 タイル違った。** `Ore::laid_out` は畑の中心を
`tiles / 4` と `3 × tiles / 4` に置き、**タイルの中心**との距離が `radius` 以下なら鉱石を入れる。
円が横にいちばん広がるのは中心を通る行なので、縁の輪（タイル 0 と `tiles-1`。`floor_picture` が
ただの地面として描く）に掛からない十分条件は

```
tiles / 4 − radius − 0.5 > 0   ⇔   tiles > 4 × radius + 2
```

で、**答えは `4 × radius + 2` より大きい最小の整数**。既定の半径 3 では **15** であって、
計画書に書かれた `4 × (radius + 1)` の **16** ではない（`radius + 1` は「タイルの中心が半タイル
ずれている」ぶんを 1 タイルに切り上げている）。実害はどちらも無い（既定の `map_tiles` は 32）が、
導出は導出なので `Ore::smallest_map` に式を置いた。

**そして最初に書いたテストが落ちて、主張の側が間違っていることが分かった。** 「この大きさなら
掛からない、1 タイル小さいと掛かる」を半径 7 通りで敷いたら、半径 0.5 で後半が落ちた。理由は
円であること: 中心を通る行は `tiles / 4 − 0.5` が整数のときしか**実在の行ではなく**、そうでない
ときは円がタイルのある高さでは少し細いので、1 タイル小さくても縁に届かない。だから式は
**保証（十分条件）**であって毎回ちょうどの最小ではない。**1 タイル大きすぎる下限は下限だが、
1 タイル小さすぎる下限は壁の中の鉱石**なので、式はそのままにしてテストを 2 つに割った:

* 半径 7 通りで「この大きさなら縁に掛からず、鉱石はある」（保証の側）;
* 遊ぶ半径 3 では**ちょうど最小**（14 タイルだと掛かる）、半径 0.5 では**1 タイル早く**
  空く（4 タイルでも掛からない）—— rustdoc の最後の段落そのもの。

紙の上で足りなかったのは「タイルの中心が 0.5 ずれている」ことと「畑は円であってマス目ではない」
ことの 2 つだった。

**`ore_patch_radius` が設定に残る理由もここで決まった。** 下限は `main()` の中、`Map` を作る前に
要る — そこにはまだ VM が無く、`data.rb` を読む手段が無い。だから畑の半径は「遊びの数」ではなく
**「遊ぶ前に世界を組む数」**として設定に残す（§4）。
