## 2. (1)(2) palette — 絵をどこから持ってくるか

最初に詰まったのはここで、**タイルシートが配列テクスチャだから**である。
`draw::start_drawing` は `ImageArrayLayout::RowHeight` で 1 タイル 1 層の配列として読み込む
（`TilemapChunk` がそれを要求する）。egui は自前のパイプラインで 2D テクスチャを bind するので、
`EguiUserTextures::add_image` に配列テクスチャを渡しても描けない。

試さずに捨てた案が 2 つある。**同じ PNG を設定違いでもう 1 度 load する**のは Bevy が
「同じパスを違う設定で読んだ」と警告する道（最初の設定が勝つ）。**シートの複製をもう 1 ファイル置く**のは、
ページに 5 KB を 2 回積むうえ、`tools/factory-tileset.py` の出力と手で同期する物が増える。

採ったのは **CPU 側のバイト列から切る**形。`Assets<Image>` の `data` は
`RenderAssetUsages::default()` なので残っており、層 *n* は 16×16×4 バイトの連続した塊である。
それを `egui::ColorImage::from_rgba_unmultiplied` にして `ctx.load_texture(…, NEAREST)` で 1 度だけ焼き、
`TextureHandle` を `Palette` に持つ（持つことが生かしておくことになる）。
`data.rb` を読み直したときは `Palette::forget()` で捨てる — シートは同じでも `sprite:` が別の層を指しうる。

**`Hand` を書く口を 1 つにした**（`build::take_in_hand` / `turn_the_hand`）。
`Order` と違って **message にしなかった**のは、`Order` が運ぶ「いつ意図されたか」が `Hand` には要らず
（手は状態）、message にすると palette のクリックがゴーストより 1 フレーム遅れるから。
理由は rustdoc に書いた。

## 3. (3) ゴースト — エンティティ 1 つで足跡と向きと色みを全部やる

要るものは「16 px の絵を、8 通りの向きのどれかで、2×2 まとめて、半透明に、赤くも」。
スプライトでやると足跡のぶんだけ実体が要り、向きは `Transform` と `flip_*` に割れる。
`TilemapChunk` は 4 つとも持っている — `TileData` に `orientation` と **`color`** があり
（`tilemap_chunk_material.wgsl` が `tex_color * tile.color`）、既定の白のままなら既存の 2 枚は 1 画素も変わらない。

そこで **3 枚目の chunk** を、**いちばん大きい機械の足跡と同じ大きさ**で立て、毎フレーム
`Transform` で動かす。地図と同じ大きさにしなかったのは、2048² の地図で 3 枚目の全面テクスチャ
（33 MB）を持つことになるから。`TilemapChunk` は immutable component なので大きさは spawn で決まり、
`data.rb` の読み直しでは 2 枚と一緒に despawn して立て直す。

**曲がりは `Flow` の規則をそのまま使う**。`Flow::refresh` のループの中身を
`Flow::where_it_comes_in(grid, at, out)` に切り出した — 中身はタイル自身を読まず**隣だけ**を見るので、
「まだ無いベルト」についてもそのまま答えられる。これでゴーストの曲がりと、置いた後の曲がりが
同じ 1 つの規則になった。

**赤の条件も 1 つにした**。`build::would_refuse(grid, ore, data, tile, what) -> Option<Refusal>` を作り、
`orders` の 4 つの断り（地図の外・鉱石が無い・機械が入らない・撤去するものが無い）も**そこを読む**。
緑のゴーストのあとに拒否が来ることが構造上なくなった。

**ポインタが無い走行**（コンテナ、まだ触っていないページ）は、見えている範囲の真ん中に立てる。
「どこにも無いゴースト」は手の中身について何も言わないし、`--shot` に写るのもこれである。
この 2 つの規則（egui が先・ポインタが無ければ真ん中）は `where_the_ghost_goes` という関数に切り出して
単体テストにした — 画面の絵では確かめられない半分だから。

## 6. 判定が見つけた穴 — 整数倍ズームが 1 ノッチを飲み込んでいた

判定に「`+` を 1 回押すと近くなる」を書いたら **FAIL** した。150 のままだった。

原因は F1 の `draw::snap_zoom` と ノッチの大きさの関係である。1 ノッチは 1/10
（`ZOOM_PER_NOTCH` 1.10）で、150 → 136.36。ところが整数倍ズームの隣どうしは 3:1 と 4:1、つまり 1/3 離れていて、
136.36 を**いちばん近い整数倍に丸めると 150 に戻る**。次のフレームも同じ。
つまり **`+` と `-` は 1 度も効かず、ホイールも 1 ノッチずつでは効かなかった** —
速く回すと 1 フレームに複数のノッチが届き、丸めは 1 フレームに 1 回なので効いていた。
F1 から公開版まで誰も気づかなかったのはそのためである。

直しに**新しい数は要らなかった**。整数倍で描くなら「次の整数倍」が**次の見え方そのもの**なので、
丸めが打ち消すと分かったときは 1 段動かす: `rung`（3 は 3:1、−2 は 1:2、1 が 1:1。0 と −1 は無い）、
`half_height_of`、`step_the_zoom`（梯子の真ん中の穴を跨ぐ）。単体テストで
「1 段は必ず違う見え方」「戻ると元の段」「−2 から内は 1」を固定した。

同じ話の続きで **「全体を見る」も直した**: 素直に「地図の半分の高さ」を頼むと丸めが**内側**に落ちて、
1 列はみ出したまま「全体」と言うことがある。地図が入る段を採る（`palette::the_whole_map` が窓の高さを取るのはこのため）。

## 7. 判定 — マウスを偽装する必要があった

判定は 5 つ目のシステム `f7_checks`（step 60..80）。Bevy の system は引数 16 個までで、
`window_checks` は既に 11 個だった。カメラの 3 つは `TheEye`（`SystemParam`）に畳んだ。

**キーの偽装は F5 の作法どおり**（`ButtonInput::press` は押したフレームだけのものなので、
判定を読む側より前に並べる）。`+` の判定が最初 FAIL したのは `CameraSet::Drive` の前に並べていなかったからで、
`.before(CameraSet::Drive)` を足した（`panel_keys` と `guide_keys` について F5 が書いた 1 行と同じ理由）。

**マウスの偽装は新しかった。** `EguiWantsInput` はフィールドが private で setter が無いので偽装できない。
一方、コンテナの走行では本物のポインタがどこにあるか決まらない — ある走行は窓の外（`cursor_position()` が `None`）、
別の走行は **(77, 9) = HUD の上**で、そのときゴーストは**正しく消える**。つまり「ゴーストが出ている」判定は
さいころだった。

そこで `point_the_mouse` を書いた。**両方に言う必要がある**:
`Window::set_cursor_position`（ゲームが読む所）と `WindowEvent::CursorMoved` の message
（bevy_egui が egui のポインタを作る元）。片方だけだと 2 つが食い違う。
これで「マウスを地図の上に置く → ゴーストが出る」「palette の上に置く → 消える」が両方**確かめられる判定**になった。

**置く 2 点は窓に対する割合**である。最初は (800, 300) と (60, 820) と書いて、

## 9. 気づいた点

1. **`CameraPlugin` の利用者は Factory だけ**。計画の「共有 crate に足せば 3 本に届く」は camera については
   当たらない。`shared-crate-plan.md` §7 に足した（箱庭のホイールにも同じ「トラックパッドでは気づけない」問題がある）。
2. **`EguiWantsInput` は偽装できない**（private なフィールド、setter 無し）。「パネルの上では起きない」を
   確かめるにはマウスを動かすしかなく、動かす口は 2 つ要る。3 本目で要ったので、4 本目が要るなら
   `games_shell::checks` に上げる候補。
3. **コンテナの走行はポインタの位置が決まらない**（同じバイナリで `None` と (77, 9) の両方を見た）。
   マウスに依る判定は偽装しない限りさいころになる。
4. **本の素材**: 「丸めと刻みが同じ桁にあると、小さい入力が黙って消える」。ズームの 1 ノッチが
   1 年近く（F1 から公開版まで）効いていなかったのに、誰も気づかなかった — 速く回せば効いたから。
   **判定が「1 回押す」と書いて初めて見つかった**。
5. **`draw_palette` は Bevy の引数 16 個ちょうど**になった。次に足す人は `SystemParam` にまとめることになる
   （`f7_checks` は `TheEye` でそれをやった）。
