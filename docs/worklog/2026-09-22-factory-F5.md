### `[patch.crates-io]` を消した

`cargo update` の出力がそのまま答えだった:

```
warning: patch `sabiruby v0.5.2 (…#8d0fea29)` was not used in the crate graph
warning: patch `sabiruby-compiler v0.2.3 (…#8d0fea29)` was not used in the crate graph
warning: patch `sabiruby-serde v0.1.0 (…#8d0fea29)` was not used in the crate graph
  Adding sabiruby v0.6.1 / sabiruby-compiler v0.3.1 / sabiruby-serde v0.2.1 / sabiruby-macros v0.1.1
```

patch の git（`8d0fea2`）は 0.5.2 を名乗っており、`"0.6"` の要求を満たせない。つまり **crates.io の
0.6.1 で足りる**（この workspace が呼ぶ `declare`・`take_with_lines`・`Declared`・`Options::symbols`・
`Vm::backtrace_line`・`highlight` は全部 0.6/0.3 に入っている）。使われない patch を 3 行残すと
`cargo` の何をするにも警告 3 行が付くので、**patch ごと消した**。

- `cargo tree -i sabiruby` → `sabiruby v0.6.1` 1 本だけ（factory・garden・rubevy・rubevy-egui が全部これを指す）
- `cargo tree -d | grep '^sabiruby'` → **0 行**（VM は 1 つ）

### `pages.yml`（公開中のページのビルドに効く）

37 行目は `Cargo.lock` から `github.com/sabiruby/sabiruby#<rev>` を grep して、その rev の SabiRuby から
Playground のコンパイラを建てていた。patch が消えると **この grep が当たらなくなり、`ref` が空になる** —
`actions/checkout` は空の ref を「既定ブランチ」と読むので、**黙って VM の main から建ててしまう**。
黙って通るのが一番悪いので、次の形にした:

1. 今までどおり rev を探す（patch に戻したときに何も変えずに済む）
2. 無ければ lock が名乗る**バージョン**から `v0.6.1` というタグ名を作る（SabiRuby の公開はタグを打っている）
3. どちらでも取れなければ **step を落とす**（`exit 1`）
4. 使う ref を 1 行 echo する（CI のログに残す）

手元で 1 と 2 の両方の式を今の lock に当てて確かめた: 1 は空、2 は `v0.6.1`。
`grep -m1` を付けてあるのは、lock に `[[patch.unused]]` の節が残っている瞬間（`cargo update` 直後、
`cargo build` の前）に `name = "sabiruby"` が 2 回当たるため。

## F5-0b Factory を `Held` に乗り換える

rubevy `docs/plans/held-requests-plan.md` §4 が「games の側」と言い残していた仕事。

### 消えたもの

| 消したもの | どこ | 何行 |
|---|---|---|
| `Arms::waiting: HashMap<usize, Request>` と `Arms::forget` の片方 | `factory/src/inserters.rs` | 索引 1 つと後始末 |
| `Inserter.said_at` と `run_inserter` の `rescue`（`@broke_at`） | `factory/ruby/prelude.rb` | 25 行 |
| `Control.said_at` と `run_control` の `rescue` | `factory/ruby/control_prelude.rb` | 18 行 |
| `inserters::where_it_broke` / `control::where_it_broke` の `ivar_get` | 両 `.rs` | 2 か所 |
| `compile` の **2 パス目**（`lines_of_the_block`、`names_and_numbers` の `prelude_lines` 引数） | 両 `.rs` | 両方とも 1 パスに |

**2 パスが消えたのは副産物で、いちばん大きい。** F3 が `Program::new` を 2 回呼んでいたのは、prelude の
`rescue` が「プログラムの何行目から著者の行か」を**Ruby の中で**知る必要があったからで、その数を生成ブロックに
書き込むと生成ブロック自身の長さが変わりかねない、という循環を「ブロックの長さは中身に依らない」ことを
テストで固定して切っていた。`Script::with_prelude_lines` はその数を **Ruby の外**に置くので、循環ごと消えた。

### 乗り換えの形

* `app.hold_requests(inserters::MOVE)` 1 行（`MOVE = "factory.move"`）。
* `answer_moves`（1 本、`take_requests` を舐めて振り分ける）→ **2 本**:
  * `start_swings`: `Query<(&Inserter, &mut Held), Added<Held>>`。`Added` でよいのは
    「腕は一度に 1 つしか待たない」から（rubevy `docs/host-api.md`: 最後の 1 つを答えると component が外れ、
    次の問いで付け直されるので `loop { move }` は 1 周に 1 回 `Added` が立つ）。
  * `answer_the_rest`: `take_requests` を**残したまま**にした。hold した種類でも
    「自分のエンティティを持たないタスクの問い」と「スクリプトが終わったその tick の問い」は
    `take_requests` に出てくる、と rubevy の文書が言っている。答えないと VM の寿命ぶんタスクが駐まる。
* `finish_swings` は `Query<(&Inserter, &mut Held)>`。**歩く量は F3 と同じ** — このクエリに当たるのは
  今何かを待っている腕だけで、それが F3 の `HashMap` の中身と同じ集合。
* 撤去・差し替えの後始末は 1 行も書いていない（rubevy の removal hook がやる）。`Arms::forget` に
  残ったのは「止まった印」の掃除だけ。
* `watch_endings` は `ScriptEnded::at`。`Script` には `with_prelude_lines(program.prelude_lines)`
  （control は `+ WRAPPER_LINES`、包みの `def` の 1 行ぶん）。

### 落ちた確認 1 件 → 直した（**文面が変わった、中身は良くなった**）

ヘッドレスの一覧が 1 行だけ diff した:

```
- a control.rb that will not run leaves the factory running: control.rb:N: RuntimeError, …
+ a control.rb that will not run leaves the factory running: control.rb:N: #<NoMethodError: undefined method 'nothing' for Object>, …
```

prelude の `rescue => e … raise` が**再 raise で例外を RuntimeError にしていた**（`$!` をそのまま
上げ直していない）。`rescue` を消したので、本物の `NoMethodError` とそのメッセージが
`ScriptEnded::value` に届くようになった。`selftest-lines.md` の 3 つの一覧を新しい文面に直した。

行と場所はどちらも正しいまま: 壊れた腕は `inserter.rb:4`、壊れた control は `control.rb:2`。
**`Task::Overrun` の穴もこれで塞がっている**（`rescue => e` は `Exception` を捕まえないので、
F3 の道では溢れた腕は `inserter.rb:?` としか言えなかった）。

## F5-1〜F5-3（main を取り込んでから）

本体の指示で S11 が main に入った所で `git merge main`。衝突は `factory/src/main.rs` の 1 か所だけ
（`app.hold_requests(…)` と S11 の `SettingsRefusalsPlugin` が同じ行に足されていた）。
`Settings::positive` / `counted` と `Errands` は main 側の形がそのまま残り、F5 の新しい設定の読みと
判定はその作法に乗せた。

### 決めたこと — `data.rb` の読み直しで建物をどう扱うか

著者の指示は「地図の大きさも `ore` も変わっていなければ建物を残す／変わったら作り直す
（その前に確かめる 1 クリック）」。実装はそれを **「世界が何を索引にしているか」**で言い直した:

| 変わったもの | どうする |
|---|---|
| 読めない | **世界に触らない。** `data.rb:行` をパネルと log に。今使っている表は世界を作った表のまま |
| ベルトの速さ、レシピの時間、箱の容量、`items_per_tile` … | **組み直さない。** 表と数を差し替えるだけ。運んでいたベルトは新しい速さで運び続ける |
| 地図の大きさ／鉱石（`per_tile`・`patch_radius`・`patches`）／アイテム・機械・レシピの**並び** | **組み直す（建物は消える）。1 度目の Apply は「こうなるがよいか」を言うだけ**、同じテキストでもう 1 度 Apply すると実行 |

3 行目の線引きの理由は 1 つ: **世界の中の数は全部この 3 つへの添字**である。タイル番号は地図の
大きさを前提にし、ベルトの上のアイテムは `data.rb` のアイテムの番号で、格子の機械は機械の番号。
どれか 1 つが動くと世界の中の全部の数の意味が変わるので、組み直す以外に正しい選択肢が無い。
逆に、それ以外の数は毎フレーム `Rules` から読まれているだけなので、差し替えれば済む。

確かめの 1 クリックは `DataFile::confirming`（同じテキストが 2 回来たら実行）。
**ゲームの側に置いた**のは、これが「窓の作法」ではなく「工場の事実」だから — 判定は窓なしでも
同じ道を通る（`window::Reread` メッセージ）。

### 決めたこと — `Minds::own` がタイルで引く件

F3 の気づき「撤去して同じ場所に建て直すと前のスクリプトが戻る」は **そのまま残した**。
理由: セーブがタイルで引くものになった（格子がセーブそのもの）ので、「その場所の腕」という
読みが世界の他の全部と揃う。エンティティで引くと、ロードで作り直された腕は別のエンティティなので
スクリプトが付いてこない。**変えるなら** `Minds::own` のキーと `MindsSave::own`。

### 決めたこと — セーブは何を持ち、何を持たないか

持つ: 格子（建物・向き・`work`・`held`・`made`・`making`・`swinging`）、レーン（刻みの整数と
アイテム番号）、鉱石の残り、`part_of_a_step`、メモリ内のスクリプト（1 台ごと・全台）、
腕の `@memory`、control の текст・`@got`・`@won`、そして `data.rb` の印。

持たない: **タスク**（`Held` の request は VM のヒープの `ObjId`。rubevy がそう言っている）、
`inserter.rb` 自身（セーブが古いファイルの写しを持つと、後で編集したファイルの上に戻ってしまう）、
`Flow`（格子から毎フレーム導かれる）、判定の状態。

control の途中を持つ／持たないは**持つ**にした。「新しい `control.rb` は新しいゲーム」という F4 の
決定は動かしていない — ロードは新しい目標ではなく**同じゲームの続き**だから。

### 落ちた確認と直したこと（過程）

1. **ヘッドレスの走行が終わらなくなった**（`--save` の on-exit）。`stop_when_over` が
   `asked.save` を見て「まだなら立てて return」と書いたが、セーブのシステムがそれを下ろすので
   毎フレーム立て直して永久に終わらない。`Local<bool>` に。
2. **`window_checks` が `ResMut<ButtonInput<KeyCode>>` で panic**（`MinimalPlugins` に
   `InputPlugin` は無い）。窓の資源は全部 `Option`。
3. **`@memory` の判定が 6 フレームで落ちた。** 腕の最初の 1 回は **1 swing に散らしてある**
   （`prelude.rb` の `stagger`）ので、スクリプト自身の 1 行目は起動から最大 `swing_seconds` 後。
   フレーム数ではなく**その数から導いた秒**で待つ形に直したら 0.4 秒で通る。
   S7 の「秒ではなく条件で待つ」の続きで、**上限の出どころはゲーム自身の数**という所は同じ。
4. **save → load → save が一致しない。** ロードとセーブの間に step が 1 回入り、ベルトが半刻み
   進む。**`P` で止めると VM も止まる**ので、ロードしたスクリプトが `run` に着けず `@memory` が
   戻らない。→ **ポーズを 2 つに分けた**: 世界（`Paused::world`、工場の step の run condition）と
   スクリプト（VM の予算）。`P` は両方、判定は世界だけ。
5. **判定の順番**。`data.rb` を読み直して世界を組み直す判定は**判定のいちばん最後**でなければ
   ならない（判定自身の工場を道連れにする）。最初は窓の判定より前に置いて、カメラの判定が
   「勝てる工場が無い」で落ちた。`REBUILD_THE_WORLD_CHECK = 47` は順番であって閾値ではない。
6. **`Rubevy::Camera.find` が nil**。factory は `register_type` を 1 行も書いていなかった。
   rubevy は component を型レジストリ越しに触るので、`Transform` と `Camera2d` の 2 行が
   「カメラの層に探すカメラがある」の全部。prelude に log を 1 行足して分かった。
7. **偽のキーは押したフレームだけのもの**。`ButtonInput::clear` が次のフレームの頭で
   `just_pressed` を消すので、**キーを読むシステムより前に判定を並べなければ押していないのと同じ**。
   `window::panel_keys` と `games_shell::guide::guide_keys` の前に並べた（後者はそのために
   `pub` にした — 共有 crate に足りなかった口）。
8. **`P` は egui が鍵盤を欲しがっている間は読まない**（文字だから）。エディタの判定が打ち込んだ後は
   ポインタが離れても focus が残るので、判定はエディタを閉じて **1 フレーム待つ**
   （`wants_keyboard_input` はフレーム末の egui のパスで決まる）。

### 落ちた確認 9 件目 — **ブラウザだけで `playground.rb:4`**

`ScriptEnded::at` に乗り換えた副作用。ページにはコンパイラがリンクされておらず、読み込む
モジュールは**どのプログラムも `playground.rb` と名づける**（sabiruby-playground の `sabi_compile`。
F2 の気づき「ブラウザのコンパイラにファイル名を渡す口が無い」と同じもの）。F3 までは prelude の
`said_at` が名前を Ruby の中で組み立てていたので当たらなかった。

直し方は**呼ぶ側の名前を使う**: `at` は必ず prelude より後ろのフレームなので、ファイルは
ゲームが渡したファイルに決まっていて、ゲームはそれがどれか知っている。行だけを使い、名前は
`SCRIPT_FILE` / `control::SCRIPT_FILE` から書く。PC の走行は 1 文字も変わらない。
