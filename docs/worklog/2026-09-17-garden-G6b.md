# 夜はまだ暗い、説明は片方でいい — 著者の 2 回目の試遊（G6b）

2026-09-17。ブランチ `garden-g6b`、main は `3be138e`（G6 merge 済み）。
著者がもう一度ブラウザで遊んで 2 つ書き留めた: **夜がまだ暗すぎる**（G6 で 18 → 26 にしたのに）、
**説明が英日交互で読みにくい。クリックで切り替えたい**。

G6 の反省は「書いた機械の上では正しく見えていた」だった。G6b はその次で、**同じ間違いを 2 回した**
ことから始まる。夜の数字は今度は lavapipe の窓で選んだのに、それでも著者の画面では暗かった。
つまり**明るさはコードの性質ではなく、部屋にあるモニタの性質**で、こちらからは見えない。
だから今回は数字を直すだけでなく、**著者が自分で答えを出せる道具**（スライダ）を置いた。
言語の切り替えも形は同じで、「どちらを読むか」は読む人が決めることだから、ボタンにした。
以下その順で書く。

## 1. 夜 — 目標が数字で来たので、測って合わせた

指示の目標は明確だった: 真夜中の地面の平均輝度を **40〜50 / 255**（G6 は 26、午後は 81）。
測り方は G6 の worklog のとおり、`--shot --at midnight` の絵の、パネルが覆っていない
**x 690–1060, y 200–870** の切り出しの Rec.601 輝度の平均。まず G6 の `docs/garden-night.png` を
同じ手順で測って **25.9** を再現し、道具が同じものを測っていることを確かめてから始めた
（新しく撮った dial=1.0 の絵も **25.6**。世界は毎回違うのに 0.3 しかぶれないのは、
平均が 24 万画素の平均だから）。

### 探索はビルドし直さずにやった

ここで先にスライダ（§1.3）を作ったのが効いた。倍率は**設定ファイルから読む**ので、
`garden.settings.txt` に `night=1.50` と書けば再ビルドなしで別の明るさの絵が撮れる。
docker + lavapipe の 1 枚が 15 秒、`cargo build` は 7 秒とはいえ wasm を含めると話が別なので、
**4 枚の絵で倍率を決めた**:

| 倍率 | 月 lux | 環境光 | 真夜中の地面 |
|---|---|---|---|
| 1.00（G6 のまま） | 400 | 55 | 25.6 |
| 1.50 | 600 | 82 | 32.8 |
| 2.00 | 800 | 110 | 39.2 |
| （2.00 + 環境光だけ 190 に） | 800 | 190 | 41.1 |
| **採用**（倍率 1.00 に焼き直し） | **950** | **190** | **44.3** |

### 3 つの量は同じだけ効かない

上の表の 4 行目が今回いちばん役に立った測定で、**環境光を 110 → 190 に上げても輝度は 1.9 しか動かない**。
一方、月は **100 lux あたり約 3**。平均輝度を動かしているのはほぼ月（と空の色）で、環境光ではない。

それでも環境光を 190 に置いたのは、**測っているものと見たいものが違う**から。平均輝度は 24 万画素の
平均で、そのほとんどは地面。生き物は小さくて丸くて、自分の影の中にいる時間が長いので、
「甲虫が居るのが分かるか」を決めるのは環境光の側で、これは平均に出ない。G6 が書いた
「月は輪郭、環境光は影の面」はそのままで、G6b が足したのは**どちらが数字を動かすかは別の話**という一行。

空（`ClearColor`）も 2.4 倍にした（`0.06,0.08,0.17` → `0.14,0.18,0.36`）。地面を明るくして空だけ
黒いままだと、夜ではなく霧に見える。青みは 3 つとも比を保ったまま上げているので変わっていない。

### 月は 950 lux で、昼の下限 1,200 lux に肉薄する

G6 は「夜が昼になってはいけない。いちばん暗い昼は地平線の 1,200 lux だから 400 で間を空ける」と
書いていた。950 はその余白をほとんど使い切る。**それでいいと判断した根拠は、日没の前後を測ったこと**:

| 時刻 | | 地面 |
|---|---|---|
| `--at 22`（`docs/garden.png` と同じ） | 午後、太陽は 1/3 の高さ | 80 |
| `--at 24.6` | 日没直前、太陽は地平線 | 38.7 |
| `--at 26.4` | 日没直後、月が地平線 | 24.5 |
| `--at midnight` | 月が真上 | **44.3** |

**月は `-up` に向いている**ので、日没の瞬間の月は地平線に寝ていて地面をほとんど照らさない。
真上に来るのは真夜中で、夜そのものが両端の暗い山なりになっている。つまり昼と夜の差を作っているのは
「月 400 対 太陽 1,200」という大小ではなく、**光源の高さ**だった。G6 が守っていた余白は、
守る意味がそもそも薄かったことになる。日没の段（38.7 → 24.5）は数字でも目でもはっきりしている。

**採らなかった案**: 夜の中で位相に応じて倍率を変える（真夜中だけ明るくする）。これは既に月の向きで
付いている効果を二重に掛けることになるし、G6 が「`night` は `height <= 0.0` の二値で、
そこに連続量を持ち込むと publish と見た目がずれる」と書いた理由がそのまま残っている。

### スライダ — 著者に返す質問

`NightDial(f32)`（`garden/src/main.rs`）を Garden パネルに置いた。0.50〜2.00、既定 1.00、
**月・環境光・空の 3 つを同じ倍率で掛ける**。3 つ別々にしなかったのは、これは設定ではなく
**質問**だから — 「あなたの画面ではどのくらい必要か」に答えるのに 3 本のつまみを渡すのは、
質問した人に設計を押し付けることになる。値は

* **ログに出る**（`setting: night = 1.30  (remembered in garden.settings.txt)`）。ブラウザではこれが
  console で、マウスで選んだ数字を外から読める唯一の場所。
* **記憶される**（下の設定ファイル）。次に開いたときも同じ夜でないと、「この値です」と報告できない。

書き込むのは**ドラッグが終わったとき**（`Response::drag_stopped`）で、動かしている最中ではない。
庭はドラッグ中もその場で明るくなる（それがスライダの意味）が、60 Hz で `localStorage` に書き、
60 行ログを出すのは意味ではない。

**著者へ**: 焼き込むのはこの倍率 1 つです。`night` を動かして決まった数字をそのまま伝えてもらえれば、
`MOON_LUX` / `NIGHT_AMBIENT` / `NIGHT_SKY` に掛けて既定を 1.00 に戻します。

## 2. 設定の置き場所 — 既にあった 2 つの関数

記憶するものが 2 つ（夜の倍率、ガイドの言語）できたので、置き場所が要る。新しく作ったのは
`crates/rubevy-arena/src/settings.rs` の 1 ファイルだけで、中身は `key=value` の行の読み書き。

**PC とブラウザの違いは書いていない。** 両ゲームの `platform.rs` には既に `read(&Path)` /
`write(&Path, &str)` があり、PC では本物のファイル、ブラウザでは `localStorage` のキーを意味する
（G3 のセーブと、エディタが保存するスクリプトがこれを通っている）。`Settings::load` はその
**2 つを関数ポインタで受け取る**だけで、どちらなのか知らない。trait にしなかったのはこのため —
`platform::read` は両ゲーム・両ターゲットで素の `fn` なので、ポインタが一番素直に嵌まる。

JSON にしなかったのは sabibots が JSON パーサを持っていないから。2 文字の言語タグを覚えるために
`serde_json` を足すのは釣り合わない（garden の `serde_json` はセーブファイル＝文書のためのもの）。
ファイルは削除すれば既定に戻る:

```
# garden: what the panel remembers. Delete a line to go back to the default.
night=1.30
lang=ja
```

PC 側の往復（無いファイル → `set` → 次の起動で読み戻す）は `cargo test -p rubevy-arena` の
1 件で押さえた。ブラウザ側は同じ 2 関数の向こうが `localStorage` になるだけで、
**ブラウザにしか聞けない**ので headless Chromium で実際に押した（§4）。

## 3. 説明パネル — 一度に片方だけ

`Guide` に `lang: GuideLang`（`En` / `Ja`）を足し、パネルの上に `English | 日本語` の 2 つの
`selectable_label` を置いた。**`guide_text.rs` は 1 行も構造を変えていない** — 段落もキー行も
英日を両方持ったままで、描くときにどちらかを選ぶだけ。著者が日本語を自分で直す前提は変わっていない。

見た目で減ったものが 2 つある。キー表は **3 列から 2 列**になり、パネル下の締めの 1 行も片方だけになった。
増えたのはボタン 2 つ。**ボタンの文字はそれぞれ自分の言語で書いた**（"English" と "日本語"）ので、
英語を読めない人が "Japanese" を探す必要も、その逆もない。

### 窓の `id` を固定しないと、切り替えで窓が飛ぶ

実装して最初に踏んだのはこれ。`Guide` は元々「英語のタイトル」と「日本語のタイトル」を
`title` / `subtitle` として持っていて（前者が窓のタイトル、後者がその下の行）、切り替えでは
**窓のタイトルそのものが変わる**。egui は `Window::new(title)` の**タイトルを窓の id にする**ので、
クリックした瞬間に別の窓になり、動かした位置も変えた大きさも捨てて画面中央の既定サイズに戻る。
`.id(egui::Id::new("rubevy-arena-guide"))` を足して、2 つの言語が同じ窓であることを id の側で言った。
フィールドは `title_en` / `title_ja` に改名（`Guide::new(en, ja)` の呼び方は変えていない）。

### 既定はどこから来るか

順に **`--lang en|ja`**（コマンドライン） → **前回クリックした言語**（設定） → **機械の言語**。
機械の言語は PC なら `LC_ALL`/`LANG`、ブラウザなら `navigator.language` で、`ja` で始まれば日本語、
それ以外は英語（`GuideLang::of_tag`）。`--lang` を**記憶しない**のは、日本語で撮った絵のせいで
次に遊ぶ人の言語が変わってはいけないから。

HUD の 1 行（`H: help / 操作説明`）は**両言語のまま**。これは「何も選んでいない人」が最初に読む行なので、
選ばせる前に読めなければならない。

### 反射の段落を 1 つ足した（許可された 1 箇所の文面変更）

パネルは「生き物が何をするか」を説明していて、**`reflex` という言葉を一度も出していなかった**。
`beetle.rb` を開けば 6 個並んでいるもので、`docs/garden.md` は長々と説明しているのに、
ゲームの中では名前すら出てこない。英日 1 段落ずつ足した（`garden/src/guide_text.rs`）。
sabibots のガイドには元から反射の段落があるので触っていない。

### フォントを切り直した

文面が増えた（＋ボタンの「日本語」）ので `tools/subset-font.sh` を回した。
**新しい文字 14 個** — `ブ勝受始専届後瞬繰自語身返預` — が入り、`·`（中黒）が 1 つ落ちた。
中黒は G6 の英日併記の締めの行だけが使っていた文字で、HUD の `·` は egui の既定フォント
（Ubuntu-Light）が持っているので落ちても何も変わらない。**62,780 → 66,796 バイト**、327 → 337 文字。
スクリプトが 3 つのファイルを読み直して自分で見つけるので、こちらが文字を数えることはない。

## 5. やっていないこと・迷った点

* **焼き込む倍率は著者待ち。** 既定は 1.00（＝月 950 / 環境光 190 / 空 0.14,0.18,0.36 そのまま）。
  著者が `night` を動かして決めた数字を報告してもらえれば、3 つの定数に掛けて既定に戻す。
* **PC の窓でスライダを実際にドラッグしてはいない。** lavapipe の窓にマウスを送る手段が無い。
  PC 側で確かめたのは (a) 設定ファイルを**読む**側（倍率 1.5 / 2.0 の絵が実際に違う明るさで撮れた）、
  (b) 書き込みと読み戻しの往復（`cargo test -p rubevy-arena`）。**押して書かせる**ところまで通したのは
  ブラウザだけ。
* **ブラウザの `?lang=ja` は作っていない。** ページの既定は `navigator.language` で足りており、
  クエリを増やすと「記憶しない指定」がもう 1 つ増える。`--lang` は PC の `--shot` のためのもの。
* **日本語の文面は下書きのまま**（G6 から変わらず）。足したのは反射の 1 段落だけで、
  直したら `tools/subset-font.sh` → `cargo build` → `web/build.sh all`。
* **`garden.settings.txt` / `sabibots.settings.txt` は `.gitignore` に入れた。** 遊べば生まれる
  ファイルで、リポジトリに入れるものではない。
* **測り方は G6 のままにした。** 切り出しの範囲も輝度の式も変えていない。数字を比べるためには
  ものさしが変わっていないことのほうが大事で、40〜50 という目標もそのものさしの上で言われている。
