# 箱庭 G0a・G1 — モデルを載せ、頭脳を Ruby に移す

2026-09-17。`docs/plans/garden-plan.md` の G0a（アセット）と G1（頭脳）。G0 の世界（`76b4d33`）に対して、
見た目を CC0 の `.glb` に差し替え、`Velocity` を書く仮の脳（Rust の `wander` システム）を消して、
生き物 1 体 = Ruby のタスク 1 本 + 反射タスク 4〜5 本にした。

rubevy は `fa37eaa`（`RubevySet::{Deliver,Tick,Answer}`、`budget = 0` で止まる時計、`Startup` で `ScriptWorld::vm`、
答えに Data オブジェクト）、sabiruby は 0.5.0。ロックだけのコミットを先に置いた（`eb11afb`）。

## 最初に転んだところ: bevy 0.19.1 に `bevy_gltf` が「無い」

`bevy` の features に `bevy_gltf` を足したら、cargo が

```
error: failed to select a version for the requirement `bevy_gltf = "^0.19.1"`
candidate versions found which didn't match: 0.19.0, 0.19.0-rc.3, ...
```

と言う。`bevy_internal 0.19.1` が `bevy_gltf ^0.19.1` を要求し、それが無い、という顔をしている。
rubevy が `bevy ^0.19.1` を要求しているので 0.19.0 に落とすこともできない（試した: 今度は
`versions that meet the requirements ^0.19.1 are: 0.19.1 / previously selected package bevy v0.19.0` で衝突する）。

crates.io の index を直接引いたら 0.19.1 は**ある**:

```
$ curl https://index.crates.io/be/vy/bevy_gltf | …
['0.19.0-rc.1', '0.19.0-rc.2', '0.19.0-rc.3', '0.19.0', '0.19.1', '0.20.0-rc.1']
```

原因はローカルの sparse index キャッシュ（`~/.cargo/registry/index/*/.cache/be/vy/bevy_gltf`）が
0.19.1 の公開より前のもので、`cargo update` はグラフに入っている crate しか引き直さないこと。
`bevy_gltf` はそれまでグラフに無かったので、ずっと古い行を読んでいた。該当の 3 ファイルを消したら一発で解決した。
**「crates.io に無い」と cargo が言うときは、まずキャッシュを疑う。** 依存のダウングレードを検討するのはその後。

## bevy 0.19 では `Scene` が `WorldAsset` になっている

`Handle<Scene>` と `SceneRoot` で書いたら `expected a type, found a trait`。
0.19 の `bevy_scene` は次世代の BSN シーン（`Scene` は trait）で、**旧来の `.glb` を読み込んだ結果は
`bevy_world_serialization` の `WorldAsset`、それを置くコンポーネントは `WorldAssetRoot`** に改名されていた
（`bevy_world_serialization-0.19.1/src/components.rs:15` に "This was recently renamed from `SceneRoot`" と書いてある）。
`bevy_gltf` feature が `bevy_world_serialization` を連れてくるので、依存を足す必要は無い。
`GltfAssetLabel::Scene(0).from_asset(...)` の名前だけは `Scene` のまま。

## アセット（G0a）

計画の条件は CC0・`.glb`・合計 2 MB 以内・10 ファイル以内。候補として挙がっていた
Quaternius「Ultimate Animated Animals」は、Google Drive の公開フォルダを
`https://drive.google.com/embeddedfolderview?id=…#list`（JS 抜きの HTML が返る）で覗いて中身を確認した:
License.txt は CC0、しかし**中身は Alpaca / Bull / Cow / Deer / Donkey / Fox / Horse / Horse_White /
Husky / ShibaInu / Stag / Wolf の 12 種で、ウサギも甲虫も無い**。形式も `.gltf`（`.bin` 別ファイル）で、
計画の `.glb` 縛りに合わない。捨てた。

代わりに Kenney の 2 パックにした。どちらも配布 zip の `License.txt` に CC0 と書いてあり（`kenney.nl` の
ページの License 欄も同じ）、そのテキストを `garden/assets/models/` にファイルごと置いた。

* **Nature Kit 2.1** — `grass.glb` / `plant_bush.glb` / `tree_default.glb` / `rock_smallA.glb`。
  テクスチャを持たず（頂点色と material の色だけ）、16〜132 三角形、3〜11 KB。
* **Cube Pets 2.0** — `animal-bunny.glb`（Rabbit）と `animal-crab.glb`（Beetle）。
  **8 つのクリップ（`static` `idle` `walk` `run` `eat` `dance` + gesture ×2）を持ち、スキンは無い
  （ノードアニメーション）**ので、`AnimationPlayer` がそのまま回る。`idle` / `walk` / `eat` の 3 本を使う。
  2 体とも `Textures/colormap.png`（10 KB）1 枚を共有する。

**甲虫が無い。** Kenney の 3d 全 49 キットを `beetle|insect|ladybug|bug|scarab|…` で引いたが 1 つも無い。
Cube Pets の中で地面を歩く殻付きの生き物はカニで、同じパレット・同じクリップ名のまま使えるので、
**Beetle にはカニを当てた**。パックを混ぜるより読者に分かりやすいと判断した。`CREDITS.md` に
「ここに置いたモデルのうち、名前と中身が違うのはこれだけ」と書いた。決めきれない話ではないが、著者が嫌なら
`animal-caterpillar.glb`（578 三角形）か `animal-bee.glb`（742）に替えるのは 1 行。

合計 **7 ファイル・321,615 バイト（314 KiB）**。予算 2 MB の 16% で収まったので、止めずに進めた。

## headless はモデルを読まない

G0 は「窓と headless で世界の作り方が完全に同じ」ことを売りにしていて、headless でも
`init_asset::<Mesh>()` + `init_asset::<StandardMaterial>()` で基本形状の子エンティティを作っていた。
G0a でここを変えた: **`Look` リソースを窓のときだけ作り、spawn 系は全部 `Option<&Look>` を取る。**
headless には `Look` が無く、見た目の子だけが生えない。

理由は 2 つ。glTF を headless で読むには `MinimalPlugins` に `WorldSerializationPlugin` +
`GltfPlugin` + `AnimationPlugin` + `Image` のローダを自前で足すことになり、**確かめたい selftest が
Bevy のローダの試験になる**。もう 1 つは、それで確かめられるものが何も無いこと — Ruby から見える
コンポーネントは親が持っており、子は `WorldAssetRoot` と `Transform` だけで、selftest は 1 つも子を見ない。
`day_night` が `Option<ResMut<GlobalAmbientLight>>` を取っているのと同じ形（「レンダラが入れるものは
headless に無い」）に揃えた、と `docs/garden.md` に書いた。

## 頭脳（G1）

`garden/ruby/prelude.rb`（366 行、コメントと空行を除いて 201）+ `creatures/beetle.rb`（89 / 51）+ `creatures/rabbit.rb`（84 / 54）。
`build.rs` は G0 のものがそのまま使える（`ruby/**.rb` を全部 `include_str!` の表にする）。
コンパイルは sabibots と同じで「prelude + 生き物のファイル + `run_creature`」を 1 つのプログラムにする。

### `Rubevy::Proxy` はゲームが持つ

rubevy の prelude（`src/prelude.rb`）には `Proxy` が**入っていない**。`assets/scripts/proxy.rb` という
サンプルスクリプトとして置かれているだけで、`require` できるのは rubevy の assets を見ているアプリだけ。
なので garden の prelude に 20 行を写した。rubevy 側の注釈（「proxy はゲームの決定であって
エンジンの決定ではない」）がそのまま理由になっているので、写した旨と一緒に残した。

### `Velocity` の形

`Velocity(pub Vec2)` は**タプル構造体 1 個の中に Vec2** なので、Ruby からは `[[vx, vz]]` に見え、
書くのも `me[:Velocity] = [[vx, vz]]` になる（`docs/host-api.md`「An Array over a struct goes by
position」）。計画書の擬似コードは `me[:Velocity] = [vx, vz]` だったが、それは Vec2 に
`[vx, vz, 0]` を流し込もうとする形で、フィールド数が合わない。`act(vx, vz)` の中に 1 行で隠した。
`Hunger(f32)` / `Sight(f32)` も同じ理由で `me[:Hunger][0]` になる。

### 2 つの ask を、コンポーネントごとの glue 0 行で答える

`garden.nearest(kind)` と `garden.count(kind)` は `answer_garden`（`RubevySet::Answer`）1 本で答える。
`match kind { "Plant" => …, "Creature" => … }` と書くと、**計画書が数えると言っている「コンポーネント
1 つあたりの Rust の接着コードの行数」が 0 でなくなる**ので、rubevy の `entities.with` と同じやり方にした:
型名 → `AppTypeRegistry::get_with_short_type_path` → `ReflectComponent::contains(entity)`。
おかげで `garden.count(:Rock)` も `garden.nearest(:Tree)` も、この関数を 1 文字も触らずに動く。
ここに書いてあるのは**ゲームの規則**だけ — 半径は聞いた本人の `Sight`、自分自身は返さない。

### 「ate」は 1 食につき 1 回

G0 の `eat` は接触しているフレームごとに `publish(… "ate" …)` していた（誰も購読していなかったので
何も起きなかった）。G1 で購読すると、1 回の食事（1〜2 秒）で 60〜120 通が届き、キュー 64 が 1 つの
出来事で埋まり、反射が毎フレーム起きる。G0 が `"bumped"` と `"touched"` で既にした判断
（「接触が始まったフレームだけ」）をここにも当てた。ついでに payload を「一口の価値」から
**「座った草の大きさ」**に変えた。一口の価値は `EAT_RATE * dt * FOOD_VALUE` = 常に 1.0 で、
何も言っていない数だったため。`Eaters` リソース（前フレーム食べていた生き物）が `Contacts` / `Bumps` と同じ役をする。

### selftest を通すまでに 6 回直した

計画の 3 つ目「a beetle touched by a rabbit changes heading within 0.5 s」が、最初は **60/86** しか通らなかった。
順に潰した。落ちた理由は 6 つとも別で、6 つとも「反射が動かなかった」のではなかった。

1. **ウサギは後ろから来る。** ウサギの脳は「腹が減っていなければ一番近い Creature が Beetle なら近づく」なので、
   接触は必ず追いかけた側から起きる。甲虫が「相手から真っ直ぐ逃げる」と、**それは今歩いている向きの
   continuation**であって、向きは変わらない。`flee_from` に `swerve:` を足し、逃げる向きを横にずらした。
   → 84/121。
2. **ずらす向きが足りない／方向が悪い。** 最初は `swerve` を「逃げる向きに ±0.7 rad、符号は交互」にしたが、
   逃げる向きが元の進路から −0.7 rad 側にあると打ち消し合う。**符号を「今の進路からより遠ざかる側」に選び**、
   大きさを 1.0 rad にした（判定の閾値は `dot < 0.7`、つまり 45.6 度）。→ 63/71。
3. **壁。** 残った 6 件を `GARDEN_DEBUG=1` で吐かせたら、`Vec2(-1.0, 0.0)` → `Vec2(-1.0, 0.0)` のように
   成分がきれいに 0 のものばかりだった。`move_creatures` は壁で `Velocity` の成分を 0 にするので、
   **壁際の生き物は向きを変えても `Velocity` からは同じ向きに見える**。反射が失敗したのではなく、
   観測ができない。壁から 1.5 以内では記録も判定もしないことにした（`by_a_wall`）。→ 50/51。
4. **最後の 1 件はハンドルの取り合いだった。** 反射は 1〜2 フレームで `act` するが、脳は
   `me[:Hunger]` → `garden.nearest` → `plant[:Transform]` → `act` で 4〜5 フレームかかる。
   反射がその途中で走ると、**脳がその後に出す `act` が反射を上書きする**（コンポーネントの書き込みは
   last-writer-wins）。見た目は「反射が動かなかった」と区別がつかない。
   `Creature#act` に**ハンドル**を入れた:

   ```ruby
   def act(vx, vz)
     return if @wheel && @wheel != Task.current
     me[:Velocity] = [[vx.to_f, vz.to_f]]
   end
   ```

   持ち主はフラグではなく `Task` なので、ハンドルを取った反射自身の `act` は通る。
   sabibots の prelude が「a reflex that wants the wheel for a while has to say so and the brain has to
   leave it alone」と書いている問題の、書き方だけを一段進めたもの。→ 51/51（ただし 3 回に 1 回、1 件落ちる）。
5. **`head_to` が `@course` を更新していなかった。** 4 の後も 3 回走らせると 50/51、54/55 と 1 件ずつ落ちる。
   `flee_from` の swerve の符号は `@course`（脳が覚えている進路）から選ぶのに、`head_to`（草に向かう）は
   `@course` を触らずに velocity だけ書いていた。**草に向かって歩いている甲虫は `@course` が古い**ので、
   swerve が逆側に出て、元の向きに戻ることがある。`head_to` にも `@course = Math.atan2(dz, dx)` を入れた
   （「`@course` は『今どこへ向かっているか』であり、向きを決めるものは全部これを真にする」）。
6. **それでもまだ 1 件落ちる: キューに溜まった同じ出来事。** ウサギが甲虫を追い回すと、接触が切れて
   また付くたびに `"touched"` が出る。反射は 1 通につき 0.5 秒（`sleep 0.5`）かけるので、
   残りはキューで待つ。4 通目の 0.5 秒後に「向きは変わったか」と聞くと、答えているのは 1 通目のことになる。
   selftest 側の記録条件を「**直前 1.5 秒のあいだ一度も触られていない**甲虫だけ」にした
   （それまでは「1.5 秒以内に*記録*していない」で、記録しなかった接触が時計を進めていなかった）。
   これで「歩いていて、壁際でなく、まだ何からも逃げていない甲虫」だけを見ることになる。→ **3 回とも全部 ok**。

「夜に寝る」も 1 度落ちた（`fastest 2.000`）。原因は同じ形で、**夜の反射が `stop` した後に、
既に走り出していた脳のパスが `act` を出す**。脳の `@asleep` 分岐にも `stop` を置いた
（計画書の擬似コードが `act 0, 0; sleep 0.5; next` になっているのはこのため、と後から分かる）。
ハンドルを入れた今なら夜の反射が取ってもよいが、`stop` 1 行の方が読みやすいので残した。

### 走らせて分かった細かいこと

* `garden.nearest` が返したエンティティは**1 フレーム古い**。答えを受け取ったときには餓死していたり、
  その草が他の口に食われて despawn していたりする。そのときコンポーネントの読みは nil を返すので、
  `place_of` / `head_to` が nil を返す形にして、生き物側は `wander` に落ちるようにした。
  最初はこれが無くて、ウサギが 55 秒あたりで `NoMethodError: undefined method '[]' for NilClass` で死んでいた。
* 1 フレームあたりの命令数は、**そのフレームの数字ではほとんど 0 になる**。生き物は
  `sleep 0.2` か答え待ちで止まっているのが普通だから。ログは総数 ÷ フレーム数にした
  （Beetle 5〜7、Rabbit 16〜18 insn/frame）。`task_location` の方は素直に効いていて、
  終了時はだいたい全員 `beetle.rb:60` / `rabbit.rb:52`（= 寝ている `sleep`）を指す。

## 未了・気づいたこと

* `--shot` の確認は docker（lavapipe）で行う。共有の named volume（`rubevy-games-target`）は
  別の担当と衝突しうるので、`rubevy-games-target-garden1` を使った。
* `web/` の同梱リストにアセットを足す作業は G5 の範囲なので触っていない。
* `WorldAssetRoot` は `Reflect` + `#[reflect(Component)]` を持つので、窓のビルドでは Ruby から
  見えうる。ただし付いているのは**見た目の子エンティティ**で、生き物の親には無いため、
  `docs/garden.md` のコンポーネント表は変わらない。
