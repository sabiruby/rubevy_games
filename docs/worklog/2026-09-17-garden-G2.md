# 箱庭 G2 — Rust の構造体を Ruby のクラスにする（`Genome`）、そして子を産む

2026-09-17。`docs/plans/garden-plan.md` の G2。`garden-g2` ブランチ、main は `a61a611`（G0 / G0a / G1 がマージ済み）、
rubevy は `fa37eaa`、sabiruby は 0.5.0。コミットは `223fc0d`（コード）と本文書を含む docs のコミット。

やったことは 3 つ。**(1)** `Genome`（速さ・視界・食欲）を `#[derive(RubyClass)]` + `#[ruby_methods]` で Ruby のクラスにし、
**(2)** 同じクラスをマクロ無しで書き直して行数を数え（数えて消した）、**(3)** 「満腹な同種 2 体が出会うと Rust が
`"mate"` を投げ、子の中身は Ruby が Rust のメソッドを呼んで決める」という繁殖を入れた。

## 0. 先に確かめたこと（計画書の「依存関係」）

計画書は「`sabiruby-macros` は `macros` feature 経由。それまでは git 直接でよい」と書いていたが、
`macros` feature は**もう入っている**（sabiruby 0.5.0、`docs/design/macros.md`「How a host depends on it」）。
なので `garden/Cargo.toml` は

```toml
sabiruby = { workspace = true, features = ["macros"] }
```

の 1 行で済んだ。`Cargo.lock` に増えたのは `sabiruby-macros` の 1 エントリだけで、**バージョンは 1 つも動いていない**
（`syn` / `quote` / `proc-macro2` は bevy 側で既にグラフに入っている）。`cargo update` は打っていない。

rubevy 側も「無いかもしれないもの」は全部あった。`ScriptWorld::vm`（`Startup` でクラスを登録する入口）、
`ScriptWorld::answer_value`（答えに Data オブジェクトを載せる）、`Arg::Value`（Hash が**コピーではなく値そのもの**で届く）
の 3 つは `fa37eaa` に入っていて、`tests/host_data.rs` がまさにこの配置の試験になっている。
**rubevy には 1 行も足していない。**

## 1. 2 つの見え方が同時に立っている

これがこの段階の主題。`Genome` に derive が 2 つ載っている:

```rust
#[derive(Clone, Copy, Debug, Reflect, RubyClass)]
#[ruby(name = "Genome")]
pub struct Genome { pub speed: f32, pub sight: f32, pub appetite: f32 }
```

* `Reflect` は bevy のもの。`Creature` の中に入れ子で置いてあるだけで、rubevy のリフレクションが
  中まで降りるので `me[:Creature][:genome]` が `{speed: …, sight: …, appetite: …}` の Hash になる。
  **`Genome` を `register_type` しなくても読める**。実際に `.register_type::<Genome>()` を外して
  40 秒回し、`me[:Creature][:genome]` が Hash として読めること（＝繁殖の判定が通ること）を確かめた。
  入れ子のフィールドは親を通って届く。行自体は残した（ゲームが Ruby に渡すつもりの型だから、
  と G3 で `Serde<CreatureSpec>` に名前で渡すから）。
* `RubyClass` は sabiruby のもの。VM の中に `HostStore<Genome>` を作り、Ruby には `(tag, handle)` を
  持つ `Data` オブジェクトを渡す。**値は Rust に残る。**

両者は互いを知らない。片方は bevy の型レジストリ、片方は VM の `TypeId` で引く store で、置き場所が違う。
`docs/garden.md` の「The genome (G2)」に、生き物がどちらをどう使い分けているかを書いた:
**自分の遺伝子はオブジェクト**（算術をするから）、**相手の遺伝子は Hash**（他エンティティのコンポーネントを
読むのは元々できることで、ゲームに 2 つ目の質問をさせる理由が無いから）。

## 2. 転んだところ: `mix(&self, other: &Genome)` は書けない

計画書の擬似コードはこう書いてあった。実際にはコンパイルが通らない。
マクロが引数を変換するのは `FromRuby` で、**参照に `FromRuby` の実装は無い**。
`docs/design/macros.md` の「What it does not cover」に書いてあるとおりで、
「ハンドルは `&T` / `&mut T` として**借りられる**が、`T` を Ruby から値で取り出すことはできない
（取り出したらそれを指している Ruby オブジェクトが古くなる）」。`&self` はその「借りる」側の話で、引数には効かない。

書けるのはこの形:

```rust
fn mix(&self, vm: &mut Vm, other: Value) -> VmResult<Genome> {
    let other = *Genome::borrow(vm, other)?;
    …
}
```

`&mut Vm` を取ると、マクロの生成コードは**レシーバを store から出して**（`take_out`）呼び、
終わったら戻す（`give_back`）。出ている間そのハンドルは予約されるので、副作用として
`g.mix(g)` は `RuntimeError: Genome is already in use by a call on the same object` になる。
`RefCell` の規則が Ruby の例外になっている形で、黙って自分自身と平均を取るより良い。
sabiruby 自身の `macros/tests/player.rs` の `greet(&self, vm, other: Value)` が同じ形だった。

## 3. 乱数をどちらから引くか

計画書は「VM の乱数（`Random`）を使う」。他に「`clock_seed` で種を撒いた自前の RNG」もありうるので、比べて VM を選んだ。

決め手は **native が受け取るのは `&mut Vm` だけ**だということ。rubevy の `docs/host-api.md`（「Adding to the VM」）が
はっきり「native から Bevy の `World` に触ろうとするな」と書いていて、実際に触れない。
つまりゲームの `Dice` リソース（世界を作るときに使っている SplitMix64）は `Genome#mutate` からは届かない。
届くのは VM の中にあるものだけで、そこには `Random` がある。

自前の RNG を `Genome` の中か `static` に置くこともできるが、それは Ruby から `srand` で手の入らない
**2 本目の運**になる。`run_creature` は既に `srand(being.me.to_i)` を呼んでいて、
世界を再生したいときに種を撒く口はそこ 1 つであってほしい。なので

```rust
fn vm_rand(vm: &mut Vm) -> VmResult<f64> {
    let name = vm.intern("Random");
    let Some(class) = vm.const_get(vm.core.object, name) else { return Ok(0.5) };
    let rand = vm.intern("rand");
    let rolled = vm.funcall(class, rand, &[], Value::Nil)?;
    f64::from_ruby(vm, rolled)
}
```

にした。`Random.rand`（引数無し）は `[0, 1)` の Float。`mutate` は 3 回引いて各遺伝子を `1 ± rate` 倍する。

## 4. 手書き版との比較（マクロ 61 行 / 手書き 113 行）

計画書の求めるもの。`garden/src/genome_by_hand.rs` に**同じ 8 メソッド**（`new`、getter 3、`mix`、`mutate`、`to_h`、`to_s`）を
`Vm::define_closure` / `install_host_store` / `data_new` / `data_of` だけで書き、
`mod genome_by_hand;` を足して**実際に release ビルドを通し**、数えてから消した。
ビルドを通していない行数は行数ではない、というだけの理由で通した。

手書き版は**わざと有利に**倒してある。藁人形と比べても意味が無いので:

* `Genome` は `Copy` なので、store から借りずに**コピーして取り出す**。マクロ版がやっている
  `take_out` / `give_back` の往復（再入時の例外つき）が要らない。
* getter 3 本は 1 つのクロージャを配列添字で共有している。
* `RubyClass` trait は使っていない。`borrow` / `handle_of` / `take_out` は derive が書くものなので、
  それを使ったら数えている当のものを借りることになる。

| | マクロ版 | 手書き |
|---|---:|---:|
| 構造体と 8 メソッド | **61 行** | **113 行** |
| VM への設置 | `Genome::register(&mut world.vm)` | `genome_by_hand::register(&mut world.vm)` |

コメントと空行はどちらも数えていない。8 メソッドの**中身（算術）は両方に入っている**ので、
差の 52 行は全部配管である: store と tag、クラスと特異クラス、返す値ごとの `data_new`、
受け取る値ごとの `data_of` と型エラー、メソッドごとの引数個数、引数ごとの `FromRuby`。
難しいものは 1 つも無く、全部「8 個のうち 1 個だけ間違っていて 1 週間気づかない」種類のものだった。

正直に 2 つ。手書き版は `define_closure`（生の `|vm, recv, args, blk|`）で書いてある。
`Vm::define_fn` は**マクロの crate ではなく VM 本体のもの**なので、手書きでもこちらを使えば
引数の個数と変換は戻ってくる（代わりに各引数の型を書き並べることになる）。
もう 1 つ、マクロ版の 61 行には `to_s` と `Random.rand` のヘルパが入っているが、手書き版にも同じものが入っている。

## 5. 繁殖: 「触れたら」はほとんど発火しない規則だった

最初の規則は計画書どおり「満腹（`Hunger >= 85`）の同種 2 体が**触れたら**」で、
触れる＝円が重なる、つまり中心距離が半径の和（甲虫 2 匹なら 0.80）以下、と書いた。**90 秒で 0 回**だった。

`GARDEN_DEBUG=1` で「満腹で待機中の同種 2 体」の距離を毎フレーム吐かせたら、40 秒間の最小が **1.24**。
1.05（半径の和 + 余裕 0.25）に一度も届いていない。理由は G0 と G1 が既に書いていたことの裏返しで:

* 2 つの円が重なっている時間は `separate` が押し戻す **1 フレームだけ**。
* しかもそのフレームに `"bumped"` が publish され、両方の `reflex(:bumped)` が**互いから逃げる**。

つまりこのゲームでは「重なっている状態」は、規則が能動的に消しにいく状態だった。
実際に「出会い」に見えるのは、**同じ草むらで一緒に食べている 2 匹**で、`eat` の届く距離
（1.1 + 草の大きさの半分）から、だいたい 2 単位くらい離れて立つ。なので `MATE_REACH = 2.0`（体 1〜2 個分以内）にした。

閾値も下げた。85 は「食後 9 秒だけ」の窓で、2 匹がその窓に**同時に・同じ場所で**入る必要がある。
90 秒に 2 回のこともあれば 0 回のこともあった。75 にした。甲虫自身のスクリプトが草を探しに行く 55 より十分上で、
親が子の代金（30）を払った後（45）より上でもある。

## 6. 費用は「子が来たとき」に払う

最初は `"mate"` を publish したフレームで両親の腹を減らし、20 秒のクールダウンを置いた。これは間違いで、
**購読していないスクリプトにも課金する**ことになる。ウサギには `reflex(:mate)` が無いので、
ウサギは何も得ずに腹だけ減る。それに、生まれたばかりの生き物はまだ購読していない（次項）ので、
最初の 1 通が落ちると 20 秒待たされる。

直した形: publish は `COURT_RETRY = 2.0` 秒ごとの再送。親の腹（`MATE_COST = 30`）と
20 秒のクールダウンは `hatch`（`garden.spawn` の答えを受けて子を実際に作るフレーム）で引く。
「規則が喋ったフレーム」ではなく「スクリプトが決めたフレーム」で払う、という形になった。
誰も聞いていない `publish` は本当に何も起こさない、が担保として効いている。

人口は規則で抑えていない。親は自分のスクリプトの「草を探す」線（55）より下に落ちるので、
食べて 75 を超え直すまで次は無い。上限 24 は規則が拾えない場合の保険で、90 秒の実測では届かない
（10 匹が 12〜19 匹になり、3〜6 匹生まれて何匹か餓死する）。

## 7. 生まれた瞬間の生き物には、まだ耳が無い

G1 の 6 つ目の判定（「ウサギに触られた甲虫は 0.5 秒で向きを変える」）が落ちるようになった。
`GARDEN_DEBUG=1` で落ちた個体を吐かせたら **age 0.9** — 生後 0.4 秒で触られていた。

`Script` が `ScriptTask` になるのは spawn の次以降のフレームで、そのタスクが最初にするのが
`start_reflexes`（購読）。だから生まれてすぐの数フレームは**誰も聞いていない**。
`"touched"` はそこに落ちて、0.5 秒後に見ると「脳の `wander` が course を振り直しただけ」の向きになっている。

これは規則の問題ではない（聞こえなかった生き物はただ歩き続ける。それで正しい）。
判定の問題なので、`startle` が selftest 用に記録する条件に「生後 2 秒以上」を足した（`NEWBORN_GRACE`）。
G1 が既に持っている 3 つの除外（止まっている / 壁際 / 直前 1.5 秒に触られた）と同じ種類の 4 つ目。

## 8. それでも 6 つ目はときどき落ちる — が、G2 のせいではない

`NEWBORN_GRACE` を入れても、4 回に 1 回くらい 1 件落ちる。**main のバイナリで測り直した**:
`a61a611`（G1 をマージ済み、G2 の変更が 1 つも入っていない）の `target/release/garden` を
90 秒 4 回回すと、42/42・**32/33**・22/22・36/36。つまり**元から落ちる**。

この枝では 3 回連続で全 8 つ ok、4 回目が 35/37。落ちた 1 件は `dot 0.78`、つまり**約 39 度は曲がっている**。
反射が動かなかったなら向きはそのまま（dot ≈ 1.0）になるはずで、39 度は脳の `wander` が
course を振り直した見た目に近い。取りこぼしか遅れであって、反射が壊れているのではない、と読める。
G1 の課題なので、ここでは追わず、`docs/garden.md` の判定 6 の説明に測った数字ごと書いた。

## 9. 細かいこと

* **kwargs は `method_missing(name, *args)` に Hash 1 個で届く。** `Rubevy::Proxy` は
  `def method_missing(name, *args, &blk)` なので、`garden.spawn(species: …, genome: …, at: …)` が
  どう届くか自信が無かった（落とされるかもしれない）。実測では `Arg::Value` の Hash 1 個。
  計画書の綴りをそのまま書けた。
* **`reflex` の枠が足りなくなった。** 甲虫は G1 で `night` / `day` / `touched` / `bumped` / `ate` の 5 つを
  使い切っていて、`REFLEX_SLOTS = 5` だった。6 にした（`run_reflex` の `when 5` と `__reflex_5` の 2 行）。
  枠が固定なのは「ブロックを名前付きメソッドにしないと `act` の中で task を park できない」
  という `docs/worklog/2026-09-16-reflex.md` の結論のため。
* **`garden.spawn` の答えは `true` か、理由の文字列。** 子を頼んで無言で何も起きないと、
  スクリプト側に調べる手がかりが無い。人口上限に当たった場合も Hash の形が違う場合も、
  何が足りないかを文字列で返して `log` させている。G3 の `Serde<CreatureSpec>` は
  ここを `TypeError` のメッセージに置き換える話なので、**今は `Vm::hash_entries` + `FromRuby` で手で読んでいる**
  （20 行。G3 の比較対象はこの 20 行）。
* **`answer_garden` は `&mut World` を持っているが `Commands` は持っていない。** 子を作るのに要るのは
  `Look` / `RubyDir` / `Assets<MrbAsset>` という普通のシステム引数なので、Hash を読む係
  （VM が要る）と生き物を作る係（VM は要らない）を `Births` リソースで分けた。
* **selftest の 8 つ目も運任せにしない。** G0 の餓死する甲虫、G1 のプローブと同じ流儀で、
  「遺伝子の違う甲虫 2 匹を、4 株の草の塊の両側 4.5 単位に、他が 8 単位以内に無い隅に置く」。
  **規則は 1 つも曲げていない**: 腹が減っているから草へ歩き、上に乗ったから食べ、食べたから満腹で、
  満腹で並んでいるから声を掛けられる。4 回連続で最初の子は 1.95 / 1.96 / 2.00 / 6.42 秒。
* 各種の**平均遺伝子**を終了時に出すようにした（`12 × Beetle: mean genome speed 2.18, …`）。
  90 秒では選択圧はほとんど見えないが、G3 以降で世界を保存して長く回すときの目印になる。

## 確認

`cargo build --release -p garden` は通る。`GARDEN_SELFTEST=1 ./target/release/garden --headless 90` を 3 回、
**8 つとも ok**（判定 6 は 35/35・31/31・44/44、最初の子は 6.42・16.47・1.95 秒、生まれた数は 4・3・6）。
`--shot` は撮り直していない: モデル・材質・光・カメラは G2 で 1 行も触っておらず、
selftest 抜きの 30 秒走行では生まれる子も 0（10 匹のまま）なので、22 秒の絵は変わらない。
