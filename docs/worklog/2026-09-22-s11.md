## 1. (1) 走行の終わり方を 1 か所に

### 何が置いてあったか — 半分ずつ 2 か所

走行が「ゲームであること」の上に頼まれることは 2 つある（判定と絵）。そのどちらも、**済んだ瞬間に自分で
`AppExit` を書いていた**ので、互いを打ち切れた。

* S9 は片方向を直した: `games_shell::checks::checks_end_the_run()` が `Args::from_env()` で `--shot` を見て、
  絵が頼まれていれば判定は終わらない。garden と sabibots がこれを使う。
* F1 と F2 はもう片方向を factory の中だけで直した: `take_shot` が `Option<Res<SelfTest>>` を読み、
  `!t.done` なら絵の後も走り続ける。

つまり**同じ 1 つの問いの半分ずつが 2 つの場所に、別々の形で**あった。その帰結が 09-21 S9（マージ）の
気づいた点で、PC の `--shot` つきの走行の最後の行が
`selftest: done — the garden keeps running (a page has nothing to exit to)` — ブラウザの理由を PC の走行が
言う嘘である。factory の `main.rs:1821` は `platform::CHECKS_EXIT_WHEN_DONE && shot.is_none()` で、
これも同じ文面を言っていた。

### 形 — `Args::from_env()` か Resource か

**Resource にした**（`games_shell::checks::Errands`）。理由 3 つ、どれも `argv` では届かないもの:

1. **半分は command line に無い。** 「絵はもう撮ったか」は走行の事実であって、走行が始まった語の事実ではない。
   `argv` に訊ける限り S9 が答えた半分しか答えられない。
2. **ページには command line が無い。** `Args::from_env()` は wasm で空を返すので、ブラウザでは
   `CHECKS_EXIT_WHEN_DONE` 以上のことを言えない。ブラウザはこの 3 本の揺れが 2 つとも出た場所である（S8、F3）。
3. 毎フレーム走る system が読む。`Args::from_env()` は訊かれるたびに command line 全部を `Vec<String>` に集める。

`Errands` は `Resource` であると同時に `Plugin` にした。ゲームが書くのは 1 行:

```rust
app.add_plugins(platform::Errands::of("the garden", selftest && headless.is_none(), shot.is_some()));
```

`impl Plugin for Errands` が自分を `insert_resource` し、`Last` に `end_the_run` を足す。
2 行（resource を入れる行と plugin を足す行）に割ると、片方を書き忘れた走行が「頼まれたことが無い走行」に
見えてしまう — 足し忘れが静かに通る形を作らないために 1 行にした。

### 「何も頼まれていない走行は終わらない」

`left()` は「まだ済んでいない errand の理由」を返し、`may_end()` は `left().is_none()` **かつ**
「何か 1 つは頼まれている」。この 2 つ目が無いと、**判定も絵も無い普通の遊びの走行が最初のフレームで終わる**。
単体テストの最後の塊がそれで、`Errands::of("the factory", false, false)` は `the_checks_are_done()` と
`the_picture_is_taken()` を両方呼んでも `may_end()` が false のままであることを確かめている。

### `done` の行 — 文面と、どの走行で出るか

`done` の行は `end_the_run` の 1 か所が書く。ゲームが渡すのは主語 1 語（`"the garden"` / `"the match"` /
`"the factory"`）だけで、文面は 1 つ:

```
selftest: done — {主語} keeps running ({理由})
```

理由は `left()` が返す 3 つのうちの 1 つで、訊く順は「この走行がまだやっていること」が先、
「台の事情」が後:

| 理由 | いつ |
|---|---|
| `the checks are not finished` | 判定がまだ（この理由で `done` の行は出ない — `done` は判定が終わった行だから）|
| `the picture is still to be taken` | **新**。PC の `--shot` つきの走行で、判定が絵より先に終わったとき |
| `a page has nothing to exit to` | ブラウザ（今までと 1 文字も変わらない）|

**9 通りの走行の行の集合は動かない**: ブラウザ 3 本の `done` の行は前と同じ文字列、ヘッドレスと窓（`--shot`
無し）は `done` の行そのものが無い（終わるから）。増えるのは `--shot` と判定を同時に使った走行だけで、
それは `selftest-lines.md` の 9 つの一覧のどれでもない。

**ただし 1 つ、前と違う形がある**: `--shot` の方が先に終わった走行（factory の既定 8 秒の絵と 13 秒の判定が
その形）では、判定が終わったフレームに残りの errand が無いので走行はそこで終わり、`done` の行は出ない。
前の factory は `shot.is_some()` を見ていたので、絵を撮った後でも `done` を言っていた。
「判定は済んだ、だが走行は続く」が `done` の行の意味なので、続かない走行が言わないのは正しい。
`selftest-lines.md` にそう書いた。

### `take_shot` は絵を撮るだけになった

3 本とも `MessageWriter<AppExit>` が `ResMut<Errands>` に替わった（引数の数は同じ — 箱庭の
`window_selftest` と Battle の `selftest` は Bevy の上限 16 個ちょうどなので、**足すのではなく入れ替える**
必要があった）。`take_shot` に残っている数（箱庭 2 秒、Battle と factory 1 秒）は
「観測者がファイルを書くのを待つ猶予」であって走行の長さではないので動かしていない
（出どころは相変わらず書いていない。§5 の気づいた点）。

factory の `watch_the_frames`（`?stress`）も `CHECKS_EXIT_WHEN_DONE` を見ていたので、同じ `errands.left()`
に替えた。stress の走行に `--shot` を付けたときだけ効く 1 行だが、直さなければ 3 か所目の同じ嘘になる。
